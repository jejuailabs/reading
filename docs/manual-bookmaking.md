# 책 공방 사용 안내

대상: 현재 로컬 온책읽기 프로토타입의 `BookWorkshop`. 진입 경로는 `/studio`이며, 기본 개발 주소를 사용할 때는 `http://127.0.0.1:3100/studio`이다. 이 문서는 실제 작성된 화면과 모델을 설명한다. 외부 출판·실시간 공동 편집·새 이미지 생성 기능이 연결되었다는 뜻은 아니다.

## 먼저 알아둘 점

- 선생님 책, 나 혼자 책, 우리 팀 책을 만들 수 있다. 화면의 역할 선택은 로컬 체험용이며 실제 교사·학생 인증을 대신하지 않는다.
- 원고는 같은 브라우저의 **IndexedDB 기기 저장소**에 보관한다. 클라우드나 다른 기기로 자동 전달되지 않는다. 이전 localStorage 자료는 원본을 남겨 두고 공통 저장 훅이 마이그레이션한다. 개인정보 대신 별명을 쓰고 실제 학생의 얼굴·이름·연락처를 입력하지 않는다.
- 저장 공간이 부족하거나 다른 탭에서 자료를 바꾸면 저장 경고가 나타난다. 현재 화면의 작업은 남아 있지만 새로고침 전에 `초안 JSON 백업`을 내려받아야 한다. 다른 탭 충돌은 현재 초안을 백업한 뒤 새로고침해서 확인한다. `저장 다시 시도`는 충돌 원본을 강제로 덮어쓰는 기능이 아니다.
- 내장 삽화 4종은 이미 준비된 샘플이다. 주제·그림체를 선택해도 새 그림이 자동 생성되거나 샘플 그림이 바뀌지 않는다.

## 1. 새 책을 준비하기

1. `책 만들기`에서 작업 방식을 고르고 `새 책`을 누른다. 기존 초안은 보관함에 남는다.
2. `씨앗 고르기`에서 제목, 주제 또는 지역, 중요한 낱말, 독자 학년 1~6, 책 유형, 원하는 그림체를 정한다.
3. 유형은 그림책·이야기책·정보책·동시집·만화·낭독극 대본을 고를 수 있다. 독자 학년은 작성자가 정하는 정보이며 자동 난도 검증 결과가 아니다.
4. 표지를 제외한 장수는 4~24장이다. 현재 초안과 다른 장수를 고르면 `새 장수로 복사`를 누른다. 짧게 줄여도 원래 페이지는 이전 초안에 남는다. 복사본 제목과 장면 순서를 확인한다.
5. 구상부터 시작하려면 `구상하기`, 곧바로 집필하려면 `바로 직접 쓰기`를 누른다.

화면의 여섯 단계는 `씨앗 고르기`(책 준비) → `이야기 그리기`(구상) → `한 장씩 쓰기`(초고) → `그림 입히기`(페이지 편집) → `다시 읽기`(검토) → `책으로 만나기`(완성본)이다. 단계 탭으로 필요한 곳을 자유롭게 오갈 수 있다.

`이전 책 공방 초안에서 시작하기`를 열면 기존 프로토타입의 원고를 새 공방으로 복사할 수 있다. 원래 초안을 덮어쓰지 않는다. 4장보다 짧은 원고에는 빈 장을 더한다. 공방의 24장·장당 6,000자·제목 120자 한도를 넘는 원고는 잘라 가져오지 않고 안내한다.

## 2. 구상과 장면 초고 쓰기

`이야기 그리기`에는 전하고 싶은 것, 시작, 가운데, 끝, 반복할 인물·소품·색, 참고자료를 적는다. 정보책에는 질문·설명·근거를, 동시집에는 각 시의 소재와 시인의 말을 적는 방식으로 안내가 달라진다.

`빈 장면에 구상 틀 넣기`는 입력한 구상을 빈 장면 메모에 배치하는 고정 규칙의 도구다. AI 생성 결과가 아니며, 이미 적은 장면 메모와 본문을 바꾸지 않는다. 장면 메모는 독자용 본문에 자동 포함되지 않는다.

`한 장씩 쓰기`에서 각 장의 메모와 본문을 직접 쓴다. 해당 장을 `그림 입히기`에서 열면 글과 그림을 함께 편집할 수 있다. 모든 장을 채울 때까지 긴 글쓰기 양식을 강제로 거칠 필요는 없고 단계 탭으로 자유롭게 이동할 수 있다.

## 3. 그림 입히기에서 페이지 편집하기

- 위쪽 페이지 번호를 눌러 이동한다. 작은 제목은 선택이며 본문은 장당 최대 6,000자이다.
- 페이지 편집에는 기본 페이지 한 장의 글과 그림을 배치한다. 만화는 칸별 장면·대사를 글로 구성하는 방식이며, 자유 배치 패널 편집기는 아직 없다. 낭독극도 해설과 대사를 직접 쓰는 문서 방식이다.
- `읽기 미리보기`는 편집 도구를 숨기고 현재 글과 삽화를 보여준다. 이전 장·다음 장으로 이동할 수 있다.
- 본문을 수정하면 출판 전 검토 확인이 다시 열린다. 이미 만든 완성본의 내용은 바뀌지 않는다.
- 원고는 입력한 언어 그대로 보존한다. 화면을 영어로 바꿔도 원고가 자동 번역되지 않는다.

## 4. 삽화 넣기와 제작 요청문 준비

### 기존 샘플 선택

바닷가·숲·밤·편지 4종 중 선택한다. 샘플을 선택하면 현재 장의 업로드 이미지를 대신한다. 업로드한 원본 파일은 사용자가 별도로 보관한다. 중요한 다른 구성을 시험하려면 먼저 `새 초안으로 복사`해서 작업한다.

### 직접 그린 이미지 업로드

`내 그림 가져오기`를 열고 `그림 파일 고르기`에서 PNG·JPEG·WebP 파일을 선택한다. 한 장 2MB 이하이며 파일 형식 표기와 실제 시그니처를 함께 확인한다. SVG와 원격 URL은 받지 않는다. 브라우저가 읽지 못하는 이미지 및 2,500만 화소 초과 이미지는 안내 후 거절한다.

업로드 후 그림을 만든 사람과 사용 허락을 적는다. 출판 검토에서 누락된 출처를 알려준다. 여러 이미지를 넣으면 브라우저 저장 공간이 먼저 부족해질 수 있으므로 작은 파일을 쓰고 저장 경고를 확인한다. 2MB는 파일당 한도이며 전체 저장 용량을 보장하는 수치가 아니다.

### 새 삽화를 만들기 위한 요청문

`그림 요청문 다듬기`를 열고 `내 설정으로 요청문 준비`를 누르면 주제·학년·화풍·반복할 인물과 소품·현재 장면을 바탕으로 요청문을 작성하고 직접 수정할 수 있다. 특정 작가나 기존 캐릭터 모방을 지시하지 않는 틀이다. 이 준비 버튼은 그림을 생성하지 않는다.

`삽화 제작 요청묶음 JSON`은 모든 장의 본문·장면·요청문·캐릭터 규격·그림 출처를 파일로 내려받는다. 상태는 `prepared_not_generated`, `generationExecuted: false`이며 검토용 준비물이다. 이미지 바이너리는 넣지 않는다. 이미지 생성·외부 전송·유료 호출은 하지 않는다. 향후 실제 생성 어댑터에 연결하려면 해당 서비스·비용·범위의 별도 승인을 먼저 확인해야 한다.

## 5. 팀으로 순서대로 작업하기

1. `우리 팀 책`을 고르고 팀 이름과 참여자 별명·맡은 일을 적는다. 최대 8명까지 보관할 수 있다.
2. 한 기기에서 순서대로 작업한다. 페이지 편집의 `지금 쓰는 사람`을 실제 차례에 맞게 고른다.
3. 본문·그림 등을 수정한 사람은 해당 장의 기여자 정보에 남는다. `내가 더한 것`에 한 일과 이유를 적고 `기여 기록 남기기`를 누르면 명시적인 과정 기록을 남긴다.
4. 친구 차례에는 현재 작가를 바꾸고 좋았던 점·궁금한 점·다음 제안을 `의견 남기기`로 기록한다. 의견은 현재 장 아래에 표시되며 본문을 자동으로 고치지 않는다.
5. `다시 읽기`에서 기여 기록을 돌아본다. 참여 횟수로 성적이나 순위를 계산하지 않는다.

다른 기기와 동시에 편집하거나 학생별 계정으로 기여를 인증하는 기능은 아니다. 현재 작가 이름은 이 기기에서 선택한 자기 기록이다. 원격 협업·접근 권한·아동 동의·외부 공개가 구현된 것으로 해석하면 안 된다.

## 6. 교사용 기존 AI 구성안 도구

교사 미리보기에서 `선생님 책`의 그림책·이야기책 `이야기 그리기` 단계에만 기존 `AiStoryPlanner`를 열 수 있다. 직접 쓰기는 AI 없이 끝까지 가능하다.

도구를 열고 별도 요청 버튼을 눌러야 새 구성안을 요청한다. 기존 텍스트 AI의 서버 연결, 승인 범위, 남은 호출 수·비용 한도 및 오류 처리를 그대로 사용한다. 한도가 없거나 연결되지 않으면 생성 완료라고 표시하지 않는다. 이번 책 공방 구현·검증에서는 유료 요청을 실행하지 않았다.

구성안을 선택하면 현재 원고를 보존한 새 초안을 만든다. AI 구상임을 표시한 메모와 검토할 지역 사실을 담고, 본문 페이지는 직접 집필할 빈 상태로 준비한다. 선택한 구상만으로 완성책이 생성되었다고 표시하지 않는다. 사실 확인 목록은 확인할 과제이며 검증된 출처 목록이 아니다.

## 7. 검토하고 고정 판본을 서재에 놓기

`다시 읽기`에서 제목, 모든 장의 본문, 팀 이름과 참여자, 업로드 이미지의 출처를 살펴본다. 정보책은 참고자료가 있어야 하며 사실과 창작 설정을 구분했는지 추가로 확인한다.

본문·순서, 권리·출처, 개인정보 항목을 확인한 뒤 `고정 판본으로 서재에 놓기`를 누른다. 이 브라우저의 서재에 해당 시점의 글·그림·출처를 복사한 새 Book을 추가한다. 같은 원고 revision은 중복 저장하지 않는다. 이후 초안을 고쳐 다시 검토하면 다른 판본을 만들 수 있다.

`책으로 만나기`의 `읽고 듣기`로 기존 읽기 화면에 들어간다. 사용자 작성 책에 상업용 AI 음원을 자동 생성하는 기능은 아니다. 사용 가능한 읽어주기 방식은 리더의 현재 기능과 기기 음성 지원에 따른다.

출판은 외부 배포·판매·공개 URL 생성이 아니라 **이 브라우저의 서재에 고정된 판본을 보관하는 것**이다. 원고·사진·그림의 권리 확인은 체크박스만으로 법적으로 보장되지 않는다.

## 8. 전권 PDF와 백업

아래쪽 `현재 초안 전권 PDF`에서 A5 또는 A4를 선택한다. 모든 장의 현재 본문과 삽화, 적어둔 출처를 포함한 PDF를 내려받는다. WebP와 내장 그림은 이 브라우저에서 JPEG로 준비하며 외부 이미지 변환 서비스를 사용하지 않는다.

PDF의 인쇄 페이지 수는 편집 화면의 장수와 다를 수 있다. 긴 본문은 추가 인쇄 페이지로 흐를 수 있다. 빈 장이 있으면 미완성 장임을 표시한다. 음성·영상·편집 기능은 PDF에 들어가지 않는다. 내려받은 PDF에서 한글, 줄바꿈, 이미지, 여백을 확인한 뒤 인쇄한다.

`초안 JSON 백업`은 현재 공방의 전체 초안을 파일로 보관한다. PDF는 읽기·인쇄 결과물이고 JSON은 수정 가능한 원고 데이터이므로 목적이 다르다. `/guide`의 공통 백업·복원에서는 공방을 포함한 작업 저장소를 함께 보관·복원한다. 전체 백업과 공방 단독 백업은 파일 범위가 다르므로 해당 화면의 지원 형식을 확인한다. 공방 자체에는 JSON 업로드 버튼이 없다.

전체 복원은 `/guide`에서 `전체 백업 파일 확인`으로 파일을 고른 뒤 확인된 저장소 수를 읽고 진행한다. `현재 자료를 먼저 내려받고, 백업에 있는 작업 저장소로 교체하는 것을 확인했어요.`에 체크해야 `백업으로 복원` 버튼을 사용할 수 있다. 누르면 현재 자료를 `onbook-before-restore.json`으로 먼저 내려받고, 해당 저장소들을 교체한 뒤 새로고침한다. 합치기 기능이 아니다. 아직 새 공방에서 열지 않은 구버전 localStorage 초안도 지원 구조를 확인해 전체 백업에 포함한다. 복원 후 공방 초안과 서재의 고정 판본을 각각 열어 확인한다.

## 검증과 한계

- `node --experimental-strip-types --test tests/book-workshop.test.ts`: 8개 테스트 통과. 새 초안 보존, 장수 축소 복사, 구상 틀의 본문 미변경, 판본 독립성, 이미지 제한, 정보책 출처·검토, 복원 데이터 검증, 그림 제작 요청묶음 상태를 확인했다.
