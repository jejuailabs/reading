# PRD 15 온책읽기 단계별 양식·보고서·PDF·인쇄

[전체 설계](../main.md) · [통합 구현 사전 브리핑](14_wholebook_implementation_brief.md)

작성일 2026-11-16 · 초등 1~6학년 · 상태: 전체 출력 계약. 기본 20양식·빈/작성본 PDF·A4/A5·전권 PDF는 로컬 구현, 학급 합본·면배치 등은 미구현.

현재 React PDF와 로컬 한글 글꼴로 실제 파일을 다운로드한다. 문항별 답변·자기 질문 가져오기·그림 응답을 지원한다. 자동 채움과 학년별 변형은 아래 계약 전체가 구현된 것은 아니며, 학년군 기록만으로 문항이 자동 변경되지는 않는다. 실제 사용법과 범위는 [학교 수업 매뉴얼](16_school_book_manual.md)을 따른다.

## 1. 제공할 결과물

웹에서 작성한 내용과 종이에 쓸 빈 양식을 같은 템플릿으로 제공한다. 버튼은 **웹에서 작성 / 빈 양식 PDF / 작성 내용 PDF / 인쇄**로 구분한다. 교사에게는 **선택한 자료 꾸러미 / 학생별 묶음 / 학급 합본**을 추가한다. 브라우저 인쇄 창의 ‘PDF로 저장’만 제공하고 PDF 다운로드를 구현했다고 표시하지 않는다.

학생 화면의 이름은 ‘읽기 수첩’, ‘내 질문’, ‘생각 나눔’, ‘돌아보기’처럼 이해하기 쉽게 한다. 보고서는 저장된 활동을 가져와 조립하며, 학생·교사에게 같은 내용을 다시 입력시키지 않는다. 모든 양식을 매 수업에 제출시키는 기본값은 금지한다.

## 3. 학년과 참여 방식 변형

| 학년군 | 쓰기 부담·표현 | 근거 표현 | 양식 구성 |
|---|---|---|---|
| 1~2 | 그림, 낱말, 한두 문장, 말한 내용을 교사가 받아쓰기 | 장면 번호·인물 행동·가리킨 그림 | 큰 글자와 넓은 그림칸; 한 장에 핵심 1~2활동; 받아쓴 기록 표시 |
| 3~4 | 짧은 문단, 사건 순서, 인물 마음 변화, 질문 수정 | 쪽/장면과 자기 말 설명 | 질문·단서·생각을 시각적으로 분리; 문장 시작 도움은 선택 |
| 5~6 | 관점 비교, 근거 묶기, 서평, 정보 출처 비교 | 다른 장면·자료를 비교하고 해석 이유 설명 | 긴 답변 자동 이어쓰기; 주장·근거·다른 해석 구획 |

같은 학년에서도 지원을 조절한다. 학년으로 글자 수 하한을 강제하지 않는다. ‘모름/아직 생각 중/이번에는 말로 나눔’을 유효한 상태로 둔다. 그림·구술을 썼다는 이유로 낮은 평가를 자동 부여하지 않는다. 기기 녹음·전사·사진 업로드는 선택 기능이고, 저장·동의·비용 조건이 준비되지 않으면 종이/구술 관찰로 참여한다.

## 4. 실제 양식 구조 예시

다음은 FORM-09의 독자 제작 예시이며, 외부 교육청·출판사 양식을 복제한 것이 아니다.

```text
나의 질문을 따라 읽기                         작성일: ____
책/판본: [자동]          읽은 곳: [장·쪽·장면]

1. 내가 알아보고 싶은 질문
   [저장한 자기 질문 / 직접 새로 쓰기]

2. 지금 내 생각은?
   [학생 글 / 그림 자리 / 말로 나눔 표시]

3. 책에서 찾은 단서
   어디에서 찾았나요? ______
   그 장면을 내 말로 설명해요. __________________
   내 생각과 어떻게 연결되나요? _________________

4. 다른 생각을 만났어요 (선택)
   [친구의 허용된 공유 생각 / 다른 장면 / 다른 자료]

5. 생각이 바뀌었나요, 그대로인가요? 그 이유는?
   ______________________________________________

6. 아직 남은 궁금함 (비워 두어도 됨)
   ______________________________________________

※ 받은 도움: 없음 / 문장 시작 / 짝 대화 / 교사 / AI 힌트
※ 내 질문은 그대로 보존됩니다. 답이 하나여야 할 필요는 없습니다.
```

교사용 FORM-02에는 `차시 / 읽을 범위 / 확보한 읽기 시간 / 핵심 질문 루틴 / 선택 활동 / 준비물 / 관찰 초점`을 둔다. 교사는 차시를 삭제·합치거나 연기할 수 있다. FORM-18에는 `관찰하지 않음`을 별도 값으로 두어 공란을 미달성으로 처리하지 않는다.

| EXP-02 | PDF 파일을 직접 생성해 다운로드 | 실제 `.pdf`, `application/pdf`, 표준 리더에서 열림; 인쇄 창만 여는 동작과 분리 |

| EXP-04 | A4 기본, A5 읽기책 별도 | 보고서와 책 본문을 혼동하지 않고 선택 출력 |
| EXP-05 | 흑백·잉크 절약·큰 글자 | 다크 모드에서도 출력은 밝은 바탕; 장식 배경 없이 내용 읽힘 |

| EXP-07 | 내용 길이에 따른 페이지 증가 | 긴 답, 표, 그림, 빈 필드·선택 섹션 처리; 내용 자동 삭제 금지 |
| EXP-08 | 머리말·꼬리말·쪽번호·판본 | 책/템플릿/작성본 revision을 추적할 수 있음 |
| EXP-09 | 학생용과 교사용 출력 분리 | 교사 메모·참고 해석·학급 명부가 학생용에 섞이지 않음 |
| EXP-10 | 학생별 분할 PDF 및 학급 합본 | 합본은 학생 경계에서 새 쪽, 명단 순서·제외 대상 반영 |

| EXP-13 | 이름 표시·익명 공개본 | 기본 범위는 비공개; 외부 공유용에는 선택한 익명 정보만 포함 |

| EXP-15 | 생성 대기·취소·실패 복구 | 실패해도 입력 유지, 동일 스냅샷 재시도; 클라우드·유료 AI로 자동 전환 금지 |
| EXP-16 | 권리별 출력 허용 | 추천만 등록한 상업책의 전문·표지·삽화를 PDF에 자동 삽입하지 않음 |
| EXP-17 | 공개·비공개 QR | QR에 학생 실명·토큰 금지; 링크 접속 시 권한 재검사; 서버 없는 로컬 출력에는 외부 QR 제공 안 함 |
| EXP-18 | 접근 가능한 대체 보기 | PDF 읽기 순서·텍스트 선택·대비 확인; PDF/UA를 검증 없이 표방하지 않고 웹 텍스트 보기 유지 |

PDF는 내려받은 뒤 원격 삭제할 수 없다. 출력 전 공유 범위를 확인하며, 다운로드 시각·대상 범위·판본·결과만 감사 기록에 남긴다. 인쇄 창을 열었다는 사건을 프린터 실제 출력 성공으로 표시하지 않는다.

## 6. 템플릿·기록·출력 데이터

아래는 신규 출력 계약의 제안이며 현재 구현된 API가 아니다. 기존 질문·독서·저작 기록은 원본 엔터티를 참조하고 보고서를 위해 다시 저장하지 않는다. `ActivityResponse`는 모듈 기록의 공통 조회 형태이며 기존 기록으로 표현되지 않는 일반 양식에만 새 응답 저장소를 사용한다.

```ts
type Stage = 'select' | 'before' | 'during' | 'inquiry' | 'discuss'
  | 'after' | 'perform' | 'create' | 'reflect';
type ResponseMode = 'text' | 'drawing' | 'oral-noted' | 'paper' | 'mixed';
type EvidenceState = 'observed' | 'self-reported' | 'not-observed' | 'not-applicable';

interface TemplateRevision {
  id: string; revision: number; formId: string; locale: 'ko' | 'en';
  stage: Stage; gradeBand: '1-2' | '3-4' | '5-6';
  blocks: TemplateBlock[]; // text, prompt, answer, drawing, table, evidence, pageBreak
  audience: 'student' | 'teacher' | 'family';
  sourceNotes: string[]; rightsReviewId?: string;
}
interface ActivityResponse {
  id: string; activityId: string; // activity_instances.id; 수업 연결 없이도 존재
  bindingContext?: { bindingId: string; bindingRevision: number }; // 원본의 소속/권한 아님
  templateRevisionId: string;
  ownerId: string; // profiles.id: 학생 소유자와 대필 기록자를 구분
  recordedByProfileId: string; groupId?: string; editionRevisionId?: string;
  anchors: EvidenceAnchor[]; fields: Record<string, FieldValue>;
  responseMode: ResponseMode; status: 'draft' | 'shared' | 'revised' | 'archived';
  revision: number; assistance: AssistanceRecord[];
}
interface ResourceRevisionRef {
  resourceType: AllowedResourceType; resourceId: string; revision: number;
}
interface ExportSnapshot {
  id: string; templateRevisionIds: string[]; sourceRevisions: ResourceRevisionRef[];
  editionRevisionIds: string[]; locale: string;
  activityIds: string[]; targetProfileIds: string[]; targetGroupIds: string[];
  resolvedFields: SnapshotField[]; // 선택·익명화 후 실제 출력할 내용의 불변 사본
  displayNames: Record<string, string>; // 출력 당시 이름/익명 이름; 권한 범위 안에서 저장
  audience: 'student' | 'teacher' | 'family';
  scope: 'blank' | 'individual' | 'group' | 'class';
  options: {paper: 'A4' | 'A5'; grayscale: boolean; largeType: boolean; booklet: boolean};
  inputHash: string; rendererVersion: string; createdAt: string;
}
```

`TemplateBlock`은 허용된 구조화 블록으로 제한하며 임의 JavaScript나 HTML을 실행하지 않는다. `AllowedResourceType`도 등록된 원본 종류만 허용하고, `ResourceRevisionRef`는 대상 존재·학교 범위·권한·불변 revision을 검증한 뒤 저장한다. 위 타입은 일부 필드를 생략한 계약 예시이며 바로 실행할 TypeScript 전체 모델은 아니다.

위 타입의 `EvidenceAnchor`는 앱 안의 문단 ID와 종이책의 판본·쪽 참조를 구분한다. 템플릿을 갱신해도 진행 중인 수업이나 이전 PDF를 자동으로 바꾸지 않는다.

학교·학급 범위는 검증된 activity에서 상속하고 실제 참여자 권한을 다시 검사한다. `scope=class`, `audience=family`, 이름 숨김 선택 자체는 접근 권한이나 외부 공유 승인이 아니다. 운영 단계에서는 서버가 원본 자료별 이용 권한·공유 승인·회수 상태를 검사한 뒤 스냅샷과 파일을 전달한다. 한 활동을 여러 수업에 연결해도 원본 응답을 복제하거나 한 `projectId`에 강제로 귀속하지 않는다.

`TemplateRevision → report_template_revisions`, `ExportSnapshot → report_snapshots`로 매핑하고 기존 `export_jobs`가 해당 스냅샷을 입력으로 삼아 `assets` 결과물을 만든다. 로컬 출력은 같은 계약을 로컬 어댑터에서 수행하며 서버 저장·감사 완료로 표시하지 않는다. 질문·응답을 수정할 때 revision을 증가시켜 이전 원본을 보존하고, 출력 스냅샷은 선택 대상·내용·이름·템플릿·렌더러 버전까지 고정한다. 일반 로그에는 출력 내용 사본을 넣지 않는다.

## 7. 구현 경로와 검증

첫 구현은 유료 PDF 변환 서비스 없이 **로컬 데이터 → 동일한 보고서 스냅샷 → 브라우저 PDF 생성·다운로드**를 목표로 한다. Firebase 운영 저장은 독립 어댑터로 붙인다. 후보 엔진은 `@react-pdf/renderer`이며, 공식 문서에서 다운로드 컴포넌트·글꼴 등록·쪽 나눔을 확인했다. 기존 React 19/Next 16, 한글 정적 글꼴, 긴 표와 대량 출력의 호환성은 기술 검증 후 확정한다. 브라우저 렌더링이라고 웹 배포의 파일 전송 비용까지 0원이라고 주장하지 않는다. [다운로드](https://react-pdf.org/docs/v4/components/pdf-download-link), [글꼴](https://react-pdf.org/docs/v4/fonts), [쪽 나눔](https://react-pdf.org/docs/v4/advanced/page-wrapping)

한글 정적 TTF/WOFF와 필요한 굵기를 허용된 라이선스로 묶는다. 공식 문서는 가변 글꼴 지원 문제를 명시하므로 웹용 가변 글꼴을 그대로 PDF에 넣지 않는다. 출력 도중 외부 CDN 글꼴·이모지·이미지를 임의로 요청하지 않는다. 큰 합본은 진행 표시와 취소를 제공하고 필요하면 나눠 생성한다. 서버 렌더링·Storage 업로드·대용량 작업은 별도 운영 비용 범위로 검토한다.

검증 고정 사례는 저학년 그림 중심 빈 양식, 중학년 질문·근거 작성본, 고학년 긴 비교 글, 한영 혼합, 이름 숨김, 학급 합본, 긴 표, A5 4/8/12쪽 면배치다. 생성 PDF를 렌더링해 모든 쪽을 확인하고 텍스트 추출·페이지 수·내용 누락을 검사한다. Chrome/Edge에서 다운로드와 인쇄를 확인하고, 실제 학교 프린터에서는 한 장 시험 출력으로 여백·양면 방향을 검증한다. 실제 기기 검증 전에는 ‘제본 출력 검증 완료’로 표시하지 않는다.

## 8. 조사와 양식 제작의 경계

교육청·출판사 자료는 수업 구성과 필요한 필드를 조사하는 근거로 활용한다. 예를 들어 경남교육청은 초등 독서인문 자료와 HWP 활동지를 제공하면서 첨부자료의 유통을 금지한다고 안내한다. 공개 다운로드 가능성이 우리 서비스 재배포 권한을 뜻하지 않는다. 본 PRD의 20종은 독자적인 필드 설계이며 기존 문서 파일을 포장해 배포하는 계획이 아니다. [경남 독서ON 자료 안내](https://www.gne.go.kr/book/user/bbs/BD_selectBbs.do?q_bbsDocNo=20260109111657956&q_bbsSn=1064)

단계별 보고서는 교사가 수업에 맞게 선택한다. 실제 교사의 수업 전후 총시간, 학생의 읽기 시간 확보, 종이 참여자의 접근 가능성을 함께 관찰해 기본 꾸러미를 조정한다.
