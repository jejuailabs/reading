# 학교 온책읽기 사용자 매뉴얼

작성 기준: 2026-11-16. 이 문서는 교사와 학생이 책을 만나고, 읽고, 질문하고, 필요할 때 작품으로 이어 가는 순서로 설명한다. 모든 활동을 차례대로 수행하거나 결과물을 제출해야 하는 서비스가 아니다.

**현재 판은 로컬 시제품용이다.** 역할 선택은 화면 미리보기이며 학교 계정 인증이 아니다. 실제 학생 개인정보·민감한 상담 내용·권한 없는 책 원문을 넣지 않는다. Firebase 운영, 실제 학급 간 공유, 실시간 공동 편집은 연결되지 않았다. 2026-11-16에 추가한 가져오기·기록지·책 공방·기기 저장은 코드가 연결되었으며, 아래에서 단위 검사와 브라우저 통합 확인을 구별한다. 모든 학교 기기와 프린터의 검증이 끝났다는 뜻은 아니다.

## 1. 지금 무엇을 사용할 수 있나요?

상태는 다음 의미로 사용한다.

- **현재 가능**: 현재 코드에서 동작과 경로를 확인했다. 별도 표시가 없으면 이번 문서 작업에서 모든 기기·인쇄 환경을 직접 시험했다는 뜻은 아니다.
- **개발 중**: 이번 작업의 구현 대상이며 완료 확인 전이다.
- **구현 확인·통합 확인 중**: 코드와 경로가 연결되어 있으나 이번 브라우저 점검의 최종 결과를 아직 반영하지 않은 기능이다.
- **운영 연결 필요**: 화면이나 로컬 체험이 있어도 실제 학교 계정·권한·여러 사용자 공유는 별도 작업이다.
- **사용 예시**: 교사가 현재 기능과 오프라인 활동을 조합하는 방법이다. 전용 자동화 기능이 있다는 뜻은 아니다.

## 2. 처음 온 선생님: 가장 짧게 한 차시 열기

### 이미 있는 책으로 시작하기 — 현재 가능

1. 왼쪽 아래 `화면 미리보기`에서 `선생님`을 선택한다.
2. `우리의 서재`에서 제목을 검색하거나 전래동화·이솝우화·창작 이야기·우리가 만든 책을 고른다.
3. 먼저 `읽기 시작`으로 책을 살핀다. 내용을 보는 것만으로 우리 반 수업이 변경되지는 않는다.
4. 이 책으로 진행하기로 했으면 `수업에 담기`를 누른다.
5. `수업 구성`에서 오늘 필요한 활동만 켠다. 읽기만 진행해도 된다.
6. `지도 미리보기`로 여정을 확인하고 수업을 시작한다. 지도 대신 목록 보기도 사용할 수 있다.
7. 학생은 화면·종이·교사의 읽어주기 중 적절한 방식으로 참여한다. 모든 아이에게 기기 입력을 시킬 필요가 없다.

책을 바꾸면 현재 여정의 참여 표시가 새로 시작되지만 이미 쓴 질문과 원고는 보관된다. 활동을 끄면 여정에서 숨겨지며 작업실 자체는 따로 열 수 있다.

### 내장 고전 밖의 책을 고르고 싶다면

서재의 `우리 반에 맞는 종이책 찾기`는 13권의 출발 목록이다. 학년 1~6과 관심 주제를 선택하고 추천 이유·읽기 지원·판본을 확인한다. `공식 서지·출판사 안내 열기`는 원래 사이트를 새 창으로 열며 앱에서 구매나 유료 가입을 실행하지 않는다.

`종이책으로 수업 시작`은 해당 판본의 **서지 정보만** 등록하고 책별 기록지를 연다. 책 전문·삽화·음원은 제공하지 않는다. 같은 ISBN으로 이미 등록한 책은 `이 종이책 수업 이어가기`로 다시 열 수 있다. 학년은 수업 설계 제안이며 해당 아이의 읽기 수준을 자동 진단한 결과가 아니다. 실제 책을 교실·도서관에서 확보한 뒤 진행한다.

`종이 참여 표시`는 현재 여정에 켜진 활동을 한꺼번에 표시하는 시제품 기능이다. 학생 한 명 한 명의 제출·출석·평가를 확인하는 기능으로 사용하지 않는다.

### 질문이나 작품 없이 마치기

책을 읽거나 듣고 바로 끝내도 된다. 독립 읽기는 제출을 요구하지 않는다. 수업 연결 읽기의 `오늘 읽기 참여 기록`은 참여의 자기 보고이며 완독 인증이나 독해 점수가 아니다. 장면을 넘겼다는 이유만으로 완독을 판정하지 않는다.

## 3. 우리 반이 읽을 책은 어떻게 넣나요?

`우리의 서재 → 내 책 가져오기` 또는 `/library/add`에서 시작한다. 아래는 현재 연결된 입력 화면의 흐름이다. 외부 자료는 먼저 내용을 확인해야 등록할 수 있다. 외부 AI·OCR·사이트 자동 수집은 실행하지 않는다.

| 가지고 있는 자료 | 입력할 내용 | 등록 뒤 기대하는 사용 | 확인해야 할 점 |
|---|---|---|---|
| 내장 고전·창작 샘플 | 서재에서 선택 | 바로 보기·읽기·듣기·질문·수업 연결 | 고전은 어린이용 재서술이며 원전의 모든 문장을 그대로 옮긴 판본이 아님 |
| 직접 쓴 원고 | 제목과 본문 붙여넣기 | 본문 읽기·장면 구분·기록지·인쇄 | 원고 언어, 제목, 장면 구분을 등록 전에 확인 |
| TXT·MD 파일 | 텍스트 파일 선택 | 추출 내용을 확인한 뒤 책 등록 | 글자가 깨지거나 기호가 섞였으면 직접 수정. 마크다운 명령을 실행하는 용도가 아님 |
| 글자가 들어 있는 PDF | PDF 파일 선택 → 추출 결과 확인 | 확인된 본문을 책으로 등록 | 원본 삽화·레이아웃은 가져오지 않음. 단·표·각주·줄바꿈을 확인 |
| 스캔 PDF | 현재는 직접 본문 입력 대안 | 서지 정보와 수동 원고로 계속 진행 | 글자 데이터가 없으면 텍스트 추출 실패를 안내. 자동 OCR이 된 것처럼 표시하지 않음 |
| 그림·사진으로 된 자료 | 이미지 선택 + 필요한 본문 직접 작성 | 그림과 직접 쓴 글을 함께 보기 | 이미지에서 글자를 자동 읽거나 새 그림을 생성하는 기능이 아님 |
| 교실에 있는 종이책 | 제목·저자·판본 등 서지 정보 | 종이책을 보며 질문·수업·기록지 사용 | 온라인 본문이 없는 책으로 명확히 구별. 근거는 종이책 쪽수·장면을 적어 사용 |
| 외부 사이트의 책·자료 | 외부 주소와 제목·설명 | 원문 사이트를 별도로 열며 활동 연결 | 주소 등록만으로 사이트를 수집하거나 책 전체를 복사하지 않음. 로그인·열람권은 원래 서비스에 따름 |

입력 순서는 다음과 같다.

1. `원고·TXT`, `PDF`, `사진·그림책`, `종이책`, `온라인 책 링크` 중 자료 종류를 고른다.
2. 책 제목과 글쓴이·판본 정보를 적는다. 본문이 있는 자료는 직접 만든 자료인지 사용 허락을 확인한 자료인지 표시하고, 전권과 발췌를 구별한다.
3. 본문·파일·이미지를 넣는다. 장면을 직접 나누려면 줄 사이에 `---`를 넣는다. 이미지 여러 장에 글을 붙일 때도 같은 구분으로 대응시킨다.
4. `본문 확인·수정`에서 순서·빠진 글·줄바꿈을 원본과 대조한다. PDF의 원래 한 쪽이 긴 경우 여러 읽기 장면으로 나뉠 수 있다.
5. `자료 이용 범위와 등록할 내용·순서를 확인했어요`에 표시하고 `확인한 책 서재에 담기`를 누른다.
6. `책 펼치기`, `온책읽기로 연결`, `서재로` 중 필요한 흐름을 고른다. 여기서 `온책읽기로 연결`은 책별 기록지를 여는 동작이며 우리 반 여정의 책을 자동 교체하지 않는다.

PDF 텍스트 추출은 표지의 제목·저자 등도 글자 데이터가 있으면 함께 가져온다. 책 제목·저자에 입력하는 서지 정보와 추출된 원문은 별개이므로 미리보기에서 포함할 범위를 확인한다. 원본의 삽화와 조판은 복사하지 않는다. 일부 쪽에 글자 데이터가 없어도 앞·중간·뒤의 빈 위치를 보존하며, 그림뿐인 쪽의 내용을 읽은 것으로 처리하지 않는다. 모든 쪽에 글자 데이터가 없으면 추출 실패를 알리고 직접 입력·서지 등록을 안내한다.

**등록과 수업 연결은 별개 행동**이다. 읽기만 하고 끝내거나, 교사가 서재·리더의 여정 연결 동작으로 나중에 수업을 구성할 수 있다.

현재 입력 한도는 제목 160자, 원고 20만 자·읽기 장면 200개, TXT/MD 800KB, PDF 20MB·100쪽, 이미지 PNG/JPEG/WebP 파일당 2MB·최대 24장이다. 텍스트 파일은 UTF-8을 사용한다. 큰 PDF를 나누거나 스캔의 글자를 직접 입력할 때 실제 읽을 구간을 출처 메모에 남긴다. 이미지가 글을 자동 추출하거나 번역하지는 않는다.

다른 사람이 만든 책·번역·삽화·활동지를 수업에 쓸 때는 이용 범위를 확인한다. 수업에서 볼 수 있다는 사정만으로 서비스 업로드·오디오 제작·외부 배포까지 허용되는 것은 아니다. 학생 창작물에 실명·사진·개인 경험이 들어간 경우 전시 전에 교사가 별도로 확인한다.

## 4. 학생: 책을 펼치고 나의 속도로 읽기

### 보기와 읽기

`우리의 서재 → 읽기 시작`으로 들어간다. 상단의 `나의 자유 읽기` 또는 `수업에 연결된 읽기` 표시를 확인한다. 서재에서 직접 연 책은 자유 읽기로 시작할 수 있다.

- `이전 장면`, `다음 장면`으로 이동한다. 고전은 `장면 골라 읽기`에서도 선택할 수 있다.
- `A−`, `A+`로 글자를 조절한다. 크기를 키웠을 때 화면을 확대하기보다 본문을 편하게 읽는 데 사용한다.
- 상단 `KO/EN`에서 언어를 바꾼다. 내장 고전은 한국어·영어 본문이 있다. 직접 만든 책의 빈 언어가 자동 번역된다는 뜻은 아니다.
- 다시 들어오면 저장된 마지막 읽기 위치를 사용한다. 특정 질문의 `근거 장면 다시 읽기`는 그 질문이 시작된 장면으로 이동한다.

### 함께 보기·글만·그림만

리더 위쪽에서 `함께 보기`, `글만 읽기`, `그림 살펴보기`를 선택한다. `함께 읽어주기 화면`은 교사가 큰 화면에서 함께 볼 때 사용할 수 있다. 그림만 보기를 선택한다고 본문을 읽은 것으로 기록하지 않는다. 내장 고전 판본에는 장면 삽화가 없으므로 그림 살펴보기는 사용하지 않는다. 종이책·외부 링크의 서지 전용 자료는 온라인 본문 없이 책 정보와 외부 읽기 안내를 표시한다.

### 책갈피

마지막 읽기 위치와 책갈피는 다르다. 마지막 위치는 다음에 이어 읽을 자리이고, 책갈피는 다시 찾아오고 싶은 장면이다.

1. 원하는 장면에서 `책갈피 꽂기`를 누른다.
2. `내 책갈피` 목록에서 장면을 골라 이동한다.
3. 같은 장면의 `책갈피 빼기`로 지운다. 다른 책갈피는 남는다.

책갈피는 책·판본·장면에 연결된다. 다른 판본의 책갈피가 현재 판본으로 자동 이동하지 않는다. 서지 전용 종이책은 온라인 장면 책갈피 대신 기록지의 `읽은 쪽·장면·범위`에 실제 쪽수를 적는다.

## 5. 듣기는 어떻게 다른가요?

## 6. 궁금한 것이 생겼어요: 질문부터 남기기

### 내 질문으로 시작하기 — 현재 가능

1. 책에서 `내 질문 남기기`를 누른다. 책과 장면이 질문에 연결된다. 책 없이 `/inquiry`에서 경험이나 주제로 시작해도 된다.
2. 다른 사람의 질문을 보기 전에 내 말로 적는다. `왜 그랬을까?`, `여기가 이상해요`처럼 미완성인 생각으로 시작해도 된다.
3. `내 질문 저장`을 누른다. 현재 입력 한도는 500자다.
4. 저장한 질문을 고른 뒤 `찾은 단서와 지금의 생각`에 적는다. 답이 아직 없어도 괜찮다.
5. 필요하면 `근거 장면 다시 읽기`로 돌아간다. 생각을 적은 뒤 `생각 기록`을 누른다.
6. 이야기로 이어 가고 싶을 때만 책 만들기로 연결한다. 질문의 답을 반드시 작품으로 제출하지 않는다.

말로 질문한 학생의 표현을 교사가 함께 적을 수 있다. 현재 시제품에서 자유 녹음·음성 자동 전사·그림 질문 업로드가 모두 구현된 것으로 해석하지 않는다.

### 내 질문을 다듬고 자란 과정 보기

1. `내 질문`에서 이미 남긴 질문을 고른다. 필요한 경우 먼저 `근거 장면 다시 읽기`로 원문을 살핀다.
2. 질문 카드의 `질문 다듬기`를 연다. `다듬을 내 질문`에 자신의 말로 수정한다. 질문은 500자까지다.
3. `달라진 이유`에는 새로 본 단서나 대화가 생각을 바꾼 까닭을 300자 안으로 적는다. 이유는 선택 사항이며 교사가 학생의 말을 받아 적어도 된다.
4. `수정한 질문과 이유 저장`을 누른다. 입력 중 자동으로 질문 원문을 교체하지 않는다. 빈 질문·그대로인 질문은 새 이력을 만들지 않는다.
5. `질문이 자란 기록`에서 처음 보관한 질문과 이후 질문·수정 이유를 시간 순서로 돌아본다. 책·근거 장면 연결, 이미 쓴 답변, 공유 설정은 그대로 남는다.

이 기능은 **내가 만든 질문**에만 표시된다. 샘플 친구의 질문을 내 질문처럼 고치지 않는다. 답변을 매번 입력하거나 공유 표시를 바꿔도 질문 성장 이력은 늘지 않는다. AI가 질문을 자동 교체하지 않으며 고친 횟수로 점수나 순위를 매기지 않는다.

예전 저장 형식의 질문에는 최초 작성 시각이 없을 수 있다. 앱이 그 시각을 추정하지 않으며 첫 수정 시 현재 질문을 함께 보존한다. 이력의 시각은 해당 문장을 보관한 때를 뜻한다. 질문별로 처음 질문을 포함한 100개 판본까지 보관하고, 한도에 도달하면 원본을 지우지 않고 추가 수정을 멈춘다. 전체 JSON 백업에는 질문 이력도 포함된다.

### 나눔터와 제출은 다른가요?

내 질문은 기본적으로 개인 질문으로 표시된다. `우리의 생각 나눔터`에 공유하는 동작과 `공유 거두기`가 있다. 현재 공유는 **같은 로컬 시제품 안의 표시 변경**이며 실제 다른 학생·다른 기기·학교 서버에 전송되지 않는다. 예시 친구 질문은 샘플이다.

교사에게 실제 과제를 제출하거나 학부모에게 전송하는 운영 기능은 연결되지 않았다. 공유 표시만 보고 제출 완료·평가 완료로 해석하지 않는다.

### AI 도움은 선택입니다

현재 질문 코칭·교사 이야기 기획에는 별도로 제한된 파일럿이 있을 수 있다. 사용 가능한 경우에도 본인 질문과 초고를 먼저 만든다. AI 결과는 제안으로 살피며 사실·작품 근거·아이에게 적절한 표현을 교사가 확인한다. 사용할 수 없거나 한도에 도달해도 직접 쓰기·정적 도움·대화는 계속할 수 있다. 샘플 구성안이나 정적 도움말을 새 AI 생성 결과로 표시하지 않는다.

## 7. 질문 기록지와 20가지 양식

책의 `이 책으로 온책읽기` 또는 `/learn/{책ID}`에서 연다. 책을 읽은 뒤만이 아니라 읽기 전·읽는 중에도 적절한 양식을 고른다. **20개를 모두 채우는 숙제가 아니다.** 학생 화면에는 교사 전용 4종을 제외한 16종이 표시되고, 교사·관리자 미리보기에서는 20종을 선택할 수 있다.

### 한 장을 골라 쓰기

1. `오늘 쓸 기록지`에서 양식을 선택하고 설명을 읽는다. `학년군`과 `직접 글쓰기 / 말을 받아 적기 / 종이에 기록`을 고른다. 학년군 선택은 기록의 맥락이며 질문 문장을 자동으로 난도 조절하는 기능은 아니다.
2. `이 양식으로 새 기록`을 누른다. 같은 양식으로 다시 만들어도 이전 기록을 덮어쓰지 않는다.
3. 필요하면 작성 영역 아래 `이 기록의 정보`에서 `기록 이름`과 `읽은 쪽·장면·범위`를 적는다. 종이책은 실제 판본·쪽수를 직접 남긴다. 원본 책과 양식의 판본은 기록을 만든 시점으로 고정한다.
4. `한 문항씩`에서 이전·다음으로 이동하거나 `전체 보기`를 선택한다. 문항마다 자신의 말로 적으며 6,000자까지 입력할 수 있다. 빈 문항이 있어도 보관할 수 있다.
5. 그림 문항에는 PNG/JPEG 2MB 이하의 직접 그린 그림을 올리거나 말로 설명할 수 있다. 이 화면의 그림 첨부는 현재 WebP를 받지 않는다. 표형 문항은 한 줄에 한 항목씩 적는 기록 칸이며 자유로운 표·관계도 편집기가 아니다.
6. `내 생각 저장`으로 저장을 요청하고 위쪽 저장 상태를 확인한다. 입력 중 자동 저장도 수행한다. 기기 저장 실패·다른 탭 충돌이 안내되면 새로고침 전에 JSON 백업을 받는다.
7. 다음에 `이 책에 남긴 기록` 목록에서 이어 쓴다. `기록 삭제`는 확인 후 해당 기록만 지우며 책과 다른 기록은 남긴다. 전체 기록 한도는 100개다.

구술 모드에서는 교사가 학생이 실제로 말한 내용을 받아 적는다. 자동 녹음·전사는 실행하지 않는다. 종이 모드에서는 모든 내용을 다시 입력할 필요 없이 읽은 범위나 돌아볼 부분만 남길 수 있다.

### 내 질문을 기록지로 가져오기

`이미 남긴 내 질문 가져오기`를 열고 이 책에서 만든 자신의 질문과 대상 문항을 고른다. `선택한 내 질문 가져오기`를 누르면 현재 답변 뒤에 질문을 덧붙인다. 원래 답변이나 질문 원본을 대체하지 않으며 자동으로 정답을 작성하지 않는다. 다른 책의 질문은 이 목록에 섞이지 않는다.

실제 본문과 자신의 질문이 있을 때 선택형 AI 질문 코칭을 열 수 있다. 사용 범위는 화면에 표시된 **현재 한 장면과 선택한 질문**이다. 책 전체를 읽고 만든 해석으로 표시하지 않는다. 실제 유료 호출은 기존 파일럿의 별도 승인·한도·사용 가능 상태를 따른다. 기록지 자체는 AI 없이 작동한다.

### 문항을 보고 막혔을 때 — AI 도움 구현 준비, 실제 생성 검증 없음

각 답변 아래 `이 문항에서 막혔나요? · AI 질문 도움`을 열 수 있다. 먼저 떠오른 자기 질문을 적고 `이 문항의 질문 힌트 요청`을 명시적으로 눌렀을 때만 기존 AI 질문 코칭을 요청한다. 선택한 내 질문이 있으면 먼저 보여 주며 직접 수정할 수 있다. 자기 질문이 아직 없으면 `이 문항에서 무엇을 살펴볼까?`라는 **앱의 도움 시작 문구**를 쓴다고 표시한다. 이를 학생이 만든 질문으로 저장하거나 평가하지 않는다.

요청에는 양식 제목·현재 문항 제목·안내와 현재 한 장면의 본문만 담는다. 학생이 쓰던 답변 전체를 자동 전송하거나 문항의 정답을 채우지 않는다. AI는 쉬운 확인 질문과 추론 힌트를 제안하며, 인용은 제공된 본문 안에 실제 있는 문구인지 서버에서 확인한다. 양식 안내를 작품 근거로 인용할 수 없다. 본문이 없거나 허용 길이를 벗어나면 요청 버튼 없이 직접 읽기 안내를 보여 준다.

결과는 `AI가 제안한 질문 도움 · 미저장`으로 표시한다. 도움 요청용 질문이나 받은 도움은 기록·질문 목록을 자동 변경하지 않는다. 남길 생각은 학생이 본래 답변 칸에 직접 쓴다. 문항·장면·언어·질문을 바꾸면 이전 응답을 버리고, 새 요청은 다시 버튼을 눌러야 한다. 요청 도중 화면을 바꿔도 이미 처리된 유료 호출이 취소되거나 환불되었다는 뜻은 아니다.

이 확장은 기존 질문 코칭의 서버 승인과 누적 호출·비용 상한을 그대로 사용하며 한도를 늘리지 않는다. **이번 구현 검증은 모의 요청만 사용했고 새 유료 AI 호출은 0회다.** 실제 모델의 교육적 도움 품질을 검증했다고 표시하지 않는다.

| 11 | 작품 돌아보기 | 책을 읽은 경험과 남은 생각을 돌아볼 때 |
| 12 | 비문학·자료 탐구 | 자료의 출처와 주장·근거를 살펴볼 때 |
| 13 | 책 소개·서평·북토크 | 다른 독자에게 책을 소개할 때 |
| 14 | 배역·해석·연습 기록 | 인물 해석과 목소리 표현의 이유를 정할 때 |
| 15 | 동화 제작 기획·검토표 — 교사 | 수업용 책의 목적과 제작·검토 기준을 정할 때 |
| 16 | 우리 책 기획·기여·수정 기록 | 개인·모둠의 창작 과정과 기여를 남길 때 |
| 17 | 서로 읽고 고쳐 쓰기 | 동료의 의견을 검토하고 반영 여부를 정할 때 |
| 18 | 수업 관찰·다음 지원 — 교사 | 필요한 학생·장면만 관찰하고 다음 지원을 정할 때 |
| 19 | 한 권 성장 포트폴리오 | 대표 기록 몇 개를 골라 변화를 돌아볼 때 |
| 20 | 학급 온책 운영·수업 성찰 — 교사 | 도서 확보·시간·업무·참여 방식을 돌아볼 때 |

질문 수·칸을 채운 비율로 자동 점수를 주지 않는다. 질문을 선택한 이유, 책의 단서, 대화 뒤 달라진 생각 또는 유지한 이유를 대표적으로 살핀다. 새 단어를 몰라 도움받는 것과 생각이 없는 것을 구별한다. 교육적 분류와 제작 기준은 [기록 양식·PDF 설계](15_report_templates_pdf_print.md)를 참고한다.

## 8. 종이와 PDF로 쓰기

### 무엇이 출력되나요?

| 진입 위치 | 동작 | 출력 범위 |
|---|---|---|
| 리더 위쪽 | 책 전체 PDF 다운로드 / 책 PDF 인쇄 미리보기 | 현재 언어의 표지와 등록된 모든 장면, A5. 서지 전용 책은 온라인 본문이 없으므로 비활성 |
| 고전 리더 기존 메뉴 | 책 전체 인쇄 | 고전 전권의 인쇄 화면 |
| 기록지 | 빈 양식 PDF | 선택한 양식의 안내와 빈 칸. 답변과 올린 그림 제외 |
| 기록지 | 작성 내용 PDF | 현재 기록의 답변·그림·책/양식 판본·읽은 범위. A4/A5 선택 |
| 기록지 | 인쇄 | `브라우저 인쇄 내용`에서 고른 빈 양식 또는 작성본 |
| 책 공방 | PDF 내려받기 | 표지와 모든 장면. A4/A5 선택, 긴 본문은 다음 출력 쪽으로 이어짐 |
| 낭독극 | 대본 인쇄 | 바람 우체국 샘플 대본 |

PDF에 음성 파일이나 재생 버튼이 포함되는 것은 아니다. 듣기는 웹 리더 또는 별도로 저장한 MP3를 사용한다. 원래 PDF를 가져온 뒤 내려받는 책 PDF는 추출·편집한 글을 새로 조판한 결과이며 원본 PDF의 배치 복제본이 아니다.

인쇄창에서 미리보기를 확인하고 용지 크기·방향·여백·축소율·머리글/바닥글을 조절한다. 학교 프린터마다 결과가 다를 수 있으므로 배부 전에 한 부를 확인한다.

### PDF의 현재 범위

전용 PDF는 브라우저에서 만들며 로컬 번들의 나눔고딕 글꼴을 포함한다. 원고·답변을 외부 변환 서버로 업로드하지 않는다. PNG/JPEG 그림을 지원하고 WebP 그림은 브라우저에서 PDF용 이미지로 변환해 넣는다. 빈 양식에는 작성 답변과 이미지가 들어가지 않는다. 기록지 브라우저 인쇄의 기본 용지는 A4이며 PDF 용지 선택은 내려받는 PDF 파일에 적용된다. 학급 전체 기록 일괄 취합, 여러 책 합본, 접어 만드는 소책자 면 배치, 자유 배치 관계도, PDF/UA 인증은 현재 제공하지 않는다.

책 공방과 리더의 전권 PDF에는 해당 책의 실제 내장 장면 삽화 또는 등록된 업로드 그림을 포함한다. 그림 없는 가져온 글이나 고전에 무관한 샘플 그림을 덧붙이지 않는다. 등록된 빈 장면도 출력에서 위치를 유지하며, 필요한 설명은 `앱 안내`라고 표시해 원문과 구별한다. 출력 결과의 그림과 빈 쪽을 미리 확인한다. PDF 엔진의 렌더 확인 결과는 아래 검증 기록에서 별도로 다룬다.

PDF 엔진의 한도는 책 200장면 또는 기록지 200항목, 문서 텍스트 합계 60만 자이다. 이미지 데이터에도 별도 합계 한도가 있어 많은 큰 그림을 넣으면 내보내기를 거절할 수 있다. 이 한도는 책 가져오기·공방·기록장의 더 작은 입력 한도를 늘려 주는 설정이 아니다. 한도 오류가 나면 그림 크기와 원고 범위를 줄여 다시 준비한다.

출력 전에는 다음을 확인한다.

1. 빈 양식인지, 학생이 기입한 양식인지.
2. 교사용 안내나 예시 답변까지 들어가는지.
3. 책 제목·판본·읽기 구간이 올바른지.
4. 긴 답변·큰 글씨·그림이 잘리거나 다음 칸을 덮지 않는지.
5. 학생 실명이나 비공개 내용이 불필요하게 포함되지 않았는지.

## 9. 선생님: 수업에 맞는 책 만들기

### 이전 편집기의 원고를 계속 쓸 때

사용 안내의 `이전 편집기의 초안을 열어요` 또는 `/studio-legacy`에서 이전 원고와 보관 초안을 연다. 기존 교재 기획의 `샘플 구성안 3개 보기`는 준비된 예시이며 입력한 학년군에 맞춰 모든 문장을 자동 변환하는 기능이 아니다.

구성안을 고른 뒤 제목과 장면 글을 직접 수정하고, 준비된 색연필 삽화 중 원하는 장면을 선택한다. 한국어·영어 글은 각각 확인한다. 미리보기에서 실제 독자가 볼 글과 그림을 살핀 후 `완성본 저장`에서 검토 확인을 한다. 완성본은 당시의 글·그림을 고정한 판본이며 이후 초고를 고쳐도 기존 판본은 바뀌지 않는다.

현재 샘플 삽화는 이 프로젝트를 위해 이미 생성해 둔 자산이다. 장면을 고르는 행동이 새 이미지 생성 요청은 아니다. 지역의 실제 사실을 넣었다면 교사가 출처와 정확성을 따로 확인한다.

### 새 책 공방에서 수업용 책 만들기

`책 만들기` `/studio`에서 `선생님 책`을 선택한다. 다음 여섯 단계는 탭으로 자유롭게 오갈 수 있고, 구상부터 시작하거나 `바로 직접 쓰기`를 선택할 수 있다.

1. **씨앗 고르기 — 책 준비**: 제목·주제 또는 지역·중요한 낱말·독자 학년 1~6·책 유형·그림체·장수를 정한다.
2. **이야기 그리기 — 구상**: 전하고 싶은 것·시작·가운데·끝·반복할 인물과 소품·참고자료를 정한다. `빈 장면에 구상 틀 넣기`는 고정 규칙으로 빈 메모를 채우며 AI 생성이 아니다.
3. **한 장씩 쓰기 — 장면 초고**: 각 장면에 자신의 말을 적는다.
4. **그림 입히기 — 페이지 편집**: 글과 이미지·장면 순서를 살핀다. `읽기 미리보기`에서는 편집 도구를 숨긴다.
5. **다시 읽기 — 검토**: 내용·권리·개인정보·독자에게 적합한 표현을 확인한다.
6. **책으로 만나기 — 완성본**: `고정 판본으로 서재에 놓기`로 당시 원고의 사본을 보관한다. 이후 초고를 수정해도 이미 만든 판본은 바뀌지 않는다.

책 유형은 그림책·이야기책·정보책·동시집·만화·낭독극 대본이다. 유형별 쓰기 안내가 달라지지만 만화 칸 자유 배치나 자동 대본 변환이 구현된 것은 아니다. 장수는 표지를 제외하고 4~24장, 장별 본문은 6,000자, 초안은 40개까지 보관한다. 장수를 줄일 때도 `새 장수로 복사`하여 원본 초안을 남긴다.

삽화는 기존 4종을 선택하거나 `내 그림 가져오기 → 그림 파일 고르기`에서 PNG/JPEG/WebP 2MB 이하의 이미지를 직접 올린다. 올린 그림의 만든 사람과 사용 허락을 적는다. 읽을 수 없는 이미지·2,500만 화소 초과 이미지는 거절한다. `그림 요청문 다듬기 → 내 설정으로 요청문 준비`와 `삽화 제작 요청묶음 JSON`은 나중에 검토할 요청문만 만드는 도구로 새 이미지·외부 전송·비용 발생을 실행하지 않는다.

선생님 책의 그림책·이야기책에서는 기존 AI 구성안 도구를 선택해서 열 수 있다. 새 호출은 기존 승인·한도·연결 상태에 따른다. 선택한 AI 구상은 현재 원고를 보존한 새 초안으로 만들며 **본문 전체를 대신 완성하지 않는다**. 지역 사실 목록은 검토할 항목이지 검증된 정보라는 인증이 아니다.

검토 단계에서는 모든 장의 본문, 권리·출처, 개인정보를 확인한다. 정보책은 참고자료와 사실 확인도 필요하다. 외부 공개·상업 출판 주문·새 AI 이미지 생성은 포함하지 않는다. 상세한 버튼·실패 처리·한도는 [책 공방 사용 안내](manual-bookmaking.md)를 참고한다.

## 10. 학생: 내 책과 우리 모둠 책 만들기

아래는 현재 새 책 공방과 오프라인 활동을 조합하는 사용 흐름이다. 현재 한 기기 편집을 여러 학생의 실시간 공동 작업으로 소개하지 않는다.

### 혼자 만드는 책

읽은 책에서 오래 남은 질문을 고르거나 자신의 경험에서 시작한다. 독자와 전하고 싶은 것을 생각한 뒤 장면별로 직접 쓴다. 처음 쓴 문장이 매끄럽지 않아도 지우고 새로 시작할 필요는 없다. 앞뒤 장면을 읽으며 사건이 이어지는지, 인물의 선택이 이해되는지 고쳐 본다.

저학년은 교사와 말로 구성하고 그림에 짧은 말을 붙이는 방식으로 참여할 수 있다. 자동 음성 전사를 요구하지 않는다. 고학년은 이야기의 전개·관점·근거를 더 살피되 AI가 대신 만든 전체 글을 자신의 쓰기 과정과 혼동하지 않는다.

### 함께 만드는 책

한 기기를 함께 보거나 정한 차례대로 작업한다. 인물·사건·글·그림·검토 역할을 나누되 다음 활동에서 역할을 바꿀 수 있다. 다른 친구의 글을 바꾸기 전에 이유를 말하고 원래 생각을 확인한다. 동료 피드백은 평가 점수보다 ‘이 부분이 이해됐어요’, ‘이 장면이 궁금해요’처럼 독자의 반응으로 남긴다.

공방에서는 `우리 팀 책`으로 시작하여 팀 이름·참여자 별명·맡은 일을 적는다. 최대 8명이며 `지금 쓰는 사람`을 차례에 맞게 바꾼다. `기여 기록 남기기`에는 더한 것과 바꾼 이유를, `의견 남기기`에는 현재 장에 대한 독자의 반응을 적는다. 피드백이 친구의 본문을 자동으로 고치지 않는다. 기록한 이름은 이 기기에서 선택한 자기 기록이며 계정 인증에 따른 저작 기여 증명은 아니다.

실제 동시 접속, 사용자별 페이지 잠금, 서버 충돌 해결, 학생 계정별 기여 인증은 운영 연결이 필요한 기능이다. 시제품의 이름·기여 메모는 실제 로그인 사용자를 인증한 기록이 아니다.

### 완성본 뒤에도 계속 쓰기

완성본을 읽어 보고 다음 초고를 수정할 수 있다. 교실 전시에 쓸 판본과 계속 고치는 초고를 구별한다. 완성본 저장은 인터넷 공개가 아니며 학부모에게 자동 전송되지 않는다.

## 11. 낭독극을 하고 싶어요 — 현재 샘플 범위

현재 `/theater`에는 `바람 우체국` 샘플 대본이 있다. 다른 책을 수업에 넣었다고 그 책의 대본이 자동 생성되지는 않는다. 원작이 다른 여정에서 열면 독립 활동이라는 안내가 나타난다.

1. `원작 보기`로 장면을 다시 읽고 인물의 마음을 이야기한다.
2. 전체 대본을 살핀 뒤 해설·소라·바람 역할을 정한다.
3. 역할 버튼으로 자신의 대사를 강조한다. 다른 대사는 맥락을 볼 수 있게 남는다.
4. 필요하면 `표현 도움 열기`를 사용한다. 한 가지 정답 목소리를 따라 하는 연습은 아니다.
5. 바람 역할이 결석했다면 해설과 함께 읽는 안내를 적용하거나 배역란을 직접 고친다.
6. `어떤 마음으로 읽었나요?`에 표현과 이유 하나를 적고 연습 기록을 저장한다.

녹음·암기·무대 장치 없이도 진행할 수 있다. 모든 고전의 검수된 대본, 4·6·8인 자동 배역, 발화량 균형 검사, 녹음 분석은 현재 샘플에 포함되지 않는다. 추가 계획은 [낭독극 PRD](04_readers_theater.md)를 참고한다.

## 13. 저장·백업·복원과 기기 바꾸기

### 현재 저장 범위

현재는 이 브라우저의 **IndexedDB 기기 저장소**에 보관한다. 탭을 닫아도 같은 브라우저·주소에서 다시 열어 이어 갈 수 있도록 구현했다. 이전 localStorage/session 자료는 원본을 보존한 채 이전한다. 단, 브라우저 데이터 삭제·사생활 보호 모드·기기 교체·브라우저의 용량 제한까지 보관을 보장하는 클라우드 저장은 아니다.

다른 탭이 먼저 같은 저장소를 수정했으면 오래된 탭이 자동으로 덮어쓰지 못하도록 충돌을 차단한다. 경고가 보이면 **현재 화면에서 개별 JSON 백업을 먼저 받고** 새로고침하여 비교한다. `저장 다시 시도`로 충돌을 강제로 덮어쓸 수는 없다. 이미지 파일당 한도와 브라우저 전체 저장 용량은 별개다.

### 전체 작업을 보관하고 옮기기

1. `사용 안내 · 백업` `/guide`를 연다.
2. `전체 작업 백업 다운로드`를 누른다. 가져온 책·그림·읽기 위치·책갈피·질문과 응답·수업 설정·완성본, 책 공방 초안, 학습 기록지의 세 저장소를 함께 보관한다. 아직 만들지 않은 저장소는 생략될 수 있다.
3. 다른 기기에서 같은 앱을 열고 `전체 백업 파일 확인`으로 `onbook-device-backup.json`을 고른다. 지원 버전·저장소 구조를 확인한 뒤에만 복원 버튼이 나타난다. 현재 업로드 한도는 200MB다.
4. 확인된 저장소 수를 읽고 `현재 자료를 먼저 내려받고, 백업에 있는 작업 저장소로 교체하는 것을 확인했어요.`에 체크한다. **합치기가 아니라 백업에 있는 해당 저장소를 교체하는 방식**이다. 체크 전에는 `백업으로 복원` 버튼을 사용할 수 없다.
5. `백업으로 복원`을 누르면 현재 자료를 `onbook-before-restore.json`으로 먼저 내려받은 뒤, 저장소들을 하나의 IndexedDB 트랜잭션으로 복원하고 화면을 새로고침한다. 손상·지원하지 않는 파일은 현재 자료를 바꾸지 않는다. 저장 공간 부족 등 복원 실패는 오류로 안내한다.

전체 백업에는 아직 새 화면에서 열지 않은 구버전 공방·기록장의 localStorage 자료도 지원 구조를 검증하여 포함한다. 다운로드된 원본 백업과 복원 전 백업을 모두 보관하고, 복원 후에는 서재의 책·책갈피·질문, 공방 초안, 학습 기록지를 각각 열어 필요한 내용이 돌아왔는지 확인한다.

기록지의 `JSON 백업`은 학습 기록지 저장소 전체, 책 공방의 `초안 JSON 백업`은 공방 초안 전체를 각각 보관한다. **개별 작업 백업은 전체 복원 파일 형식과 다르다.** 현재 `/guide`의 복원에는 전체 백업 파일을 사용한다. 개별 백업을 자동으로 합치거나 책 공방에 업로드하는 기능은 아직 없다. 저장 실패로 현재 화면에만 남은 편집은 그 화면의 개별 백업에 먼저 보관한다.

로컬 백업은 학교 서버의 자동 백업이나 계정별 클라우드 보관이 아니다. PDF는 읽고 인쇄할 결과물이고 JSON은 작업을 복원할 데이터이므로 용도가 다르다.

- 브라우저 전체 백업: 3저장소 JSON 다운로드 → 파일 확인에서 3저장소 검증 → 교체 확인 체크 → 복원 전 `onbook-before-restore.json` 다운로드 → 복원 후 새로고침을 확인했다. 재진입 후 FORM-09의 `지금의 생각` 실제 답변, 읽기 본문·2장면·책갈피 1개·글만 읽기 선택, 자기 질문과 답변, 공방 v17의 4장·직접 올린 삽화·그림 출처가 유지된 것을 각각 확인했다. 이 결과는 같은 환경의 선택한 자료에 대한 복원 확인이며 모든 기기 간 이전을 보장하는 결과는 아니다.
- 최종 `npm test`는 **92개 통과·실패 0·exit 0**, `npm run build`는 **exit 0**이다. 안내 화면의 복원 확인 체크, 최신 리더 PDF 처리, 새 디자인·글꼴·정적 아이콘을 포함하며 빌드의 TypeScript 검사도 통과했다. [실행 기록](../artifacts/latest-verification-log.md)과 [학교 책 활동 실기 요약](../artifacts/school-book-verification.md)에 검증 범위를 구분했다. 이번 기능 구현·검증에서 별도 유료 AI API나 OCR 요청을 실행하지 않았다. 디자인 아이콘 16종은 사용자가 승인한 구독 내장 이미지 생성으로 제작한 정적 자산이며 원본 PNG와 웹용 WebP를 보관한다. 화면은 저장된 자산을 표시하며 클릭할 때 새 이미지를 생성하지 않는다.
- 문항별 AI 도움은 서버 입력·결과 계약, 기존 한도 유지, 문항 변경 뒤 늦은 응답 폐기, 중복 클릭 방지·자동 재시도 없음 등을 모의 요청으로 검사했다. 실제 모델 호출이나 답변 품질 검증은 수행하지 않았다.
- 학생 질문 다듬기는 원본·이유·책/장면·답변 보존, 명시 저장과 답변 자동 저장 구분, 이전 형식 복원, 손상된 이력 거부 등을 다룬 단위 검사 6개를 통과했다. 기존 모델·기록장 회귀 검사를 포함한 21개와 전체 타입 검사도 통과했다. 실제 브라우저에서 수정 버튼으로 원본과 수정본의 이력 2개를 만들고, 원래 질문·수정 이유·기존 답변이 유지되는 것을 확인했다.

### 내 기록과 운영 화면의 의미

`내 기록과 작품` `/my-work`에서는 펼쳐 본 책 수, 만든 질문, 저장한 완성본을 본다. `펼쳐 본 책`은 완독 수나 독해 성적이 아니다. 질문을 눌러 탐구를 이어 가고 완성본을 눌러 읽을 수 있다. 기록지별 자세한 내용은 해당 책의 `/learn/{책ID}`, 공방 초안은 `/studio`에서 연다.

교사 미리보기의 `운영 현황`은 이 기기의 샘플 데이터와 연결 상태를 보여준다. 실제 학교 명부 관리·학급별 성적·출결·가정 알림·서버 분석 대시보드가 아니다. 역할을 바꾸는 동작도 로그인·권한 인증을 대체하지 않는다.

| 확인 흐름 | 이번 구현 대상 | 매뉴얼 완료 표시 조건 |
|---|---|---|
| 가져오기 → 미리 확인 → 등록 → 자유 읽기 | 본문·TXT/MD·PDF 텍스트·이미지·서지·링크 | 입력별 실제 성공·실패 화면과 제한 확인 |
| 온라인 본문 없는 책 → 질문·기록지 | 종이책/외부 링크의 서지 모드 | 빈 본문을 있는 것처럼 보여주지 않고 활동 실행 가능 |
| 읽기 방식 전환 → 책갈피 → 재진입 | 함께/글/그림 보기와 책갈피 | 마지막 위치와 책갈피 독립 유지, 삭제·복귀 확인 |
| 양식 선택 → 빈 양식/기입 결과 출력 | 20양식과 수업 계획 | 실제 목록, 필드 저장, 한글·긴 글·빈 칸 PDF 확인 |
| 교사 교재 → 완성본 → 서재 | 새 책 공방 | 초고와 판본 구분, 수정해도 이전 판본 보존 |
| 학생 개인/팀 → 순차 기여·피드백 | 새 책 공방 | 모드별 차이를 확인하고 실시간 협업이라고 설명하지 않음 |
| 브라우저 닫기 → 재개 → 백업 → 복원 | 로컬 영속 저장·JSON | 포함 범위·덮어쓰기·실패 복구 확인 |
| 읽기만 → 수업 종료 | 기능 조합 | 질문·작품 0개를 실패로 처리하지 않음 |
| 기록 공유 → 공개·가정 배부 | 이번 운영 범위 밖 | 외부 공개·학부모 전달을 구현된 기능으로 표시하지 않음 |
| 모든 책 낭독극·새 AI 낭독·OCR | 이번 운영 범위 밖 | 기존 샘플과 신규 생성 가능성을 혼동하지 않음 |

추가 개발 후보는 학교 공통 수업안 복제, 실제 도서 확보·대출 연결, 결석 학생의 재합류, 교사별 관찰 대상 순환, 판본 변경 때 근거 재연결, 종이와 온라인 기록의 중복 방지다. 필요를 확인하기 전 대시보드 항목과 필수 입력란을 늘리지 않는다.
