# 학생 공동저작·학급책 PRD

- 문서 ID: PRD-06
- 상태: 설계·로컬 프로토타입 착수. 실제 학생 수업·교사 업무량·학습 효과를 검증하기 전
- 기준일: 2026-11-16
- 대상: 초등 1~6학년 학생·모둠·학급, 담당·협력 교사
- 상위 문서: [통합 계획](../main.md)
- 연계: [읽기·질문·탐구](02_reading_inquiry_curriculum.md), [낭독극](04_readers_theater.md)
- 인증·참여자 계약: [인증과 학교 구성원 관리](07_identity_school_management.md). Google 계정이 없는 학생도 교사 관리 개별 참여자로 식별하며 공유 계정을 만들지 않는다.

## 1. 목적과 경계

학생이 읽은 작품의 인물·사건·표현을 관찰하고 자기 질문을 바탕으로 새로운 이야기를 구상하며, 친구의 반응을 받아 고쳐 쓰고 함께 책으로 완성하도록 돕는다. 결과물의 화려함보다 학생의 생각·선택·수정 과정이 남는 것이 핵심이다.

교사용 빠른 교재 제작과 학생용 공동저작은 목표와 완료 기준을 분리한다. 교사 제작은 수업용 읽을거리를 검토·완성하는 시간을 줄이는 일이다. 학생 공동저작은 계획·초안·대화·수정을 실제로 경험하는 활동이다. 학생이 주제만 입력하고 AI가 글·그림·음성을 모두 만들어 주는 흐름을 학생 저작의 기본값으로 두지 않는다.

`책 만들기 → 우리 책 만들기`에서 교사가 허용한 학급·모둠 프로젝트를 직접 열거나, 이야기 여정·질문·낭독의 연결로 같은 작업대에 들어온다. 원작 없이 지역 관찰·경험·공통 주제로 새 책이나 합본책을 시작할 수도 있다. 기획·페이지·피드백·수정·검토는 편집기 안의 단계이며 지도 장소를 하나씩 추가해 표현하지 않는다. 여정·과제는 선택 연결이고 연결 해제가 초안·기여 삭제가 되어서는 안 된다. [PRD 08](08_platform_architecture.md)의 복원·재사용·공개 범위 계약을 따른다.

### 핵심 목표

1. 구술·그림·짧은 글·긴 글 등 학년과 접근성에 맞는 표현을 지원한다.
2. 여러 사람이 한 파일에 접속하는 것을 넘어, 실제 선택과 피드백에 참여한다.
3. 학생 원문·사람의 수정·AI 제안을 구별하고 보존한다.
4. 책 제작을 위해 교사가 모든 학생 자료를 다시 옮겨 적거나 편집하지 않도록 한다.
5. AI·학생 Google 계정·개별 기기가 없어도 공동책을 완성할 수 있다.

### 초기 비목표

- 무제한 페이지·삽화·영상·음성 생성
- 학생 저작을 외부에 자동 출판·판매·공개
- 생성 결과의 저작권 성립·독창성을 자동 보증
- 필기량·타자량·AI 사용량으로 개인의 창작 기여를 자동 평가
- 교사 검토 없이 학생 글을 AI가 덮어쓰거나 최종 성적·평가를 확정

## 2. 저작 모드

| 모드 | 공동 결정 범위 | 작업 단위 | 적합한 시작 방식 | 완료물 |
|---|---|---|---|---|
| 학급 공동책 | 인물·주제·큰 사건 흐름을 학급이 함께 결정 | 짝·모둠이 한 장면 또는 한 페이지 담당 | 저학년 교사 화면 중심, 그림·구술로 참여 | 하나의 이야기 또는 주제가 연결된 학급책 |
| 모둠책 | 모둠별 독자·목적·플롯을 결정 | 같은 이야기의 여러 장면 | 중·고학년 3~4명 모둠부터 검증 | 모둠별 짧은 완결책 |
| 합본책 | 공통 주제·차례·독자만 합의 | 개인·짝의 독립 작품 | 각자의 목소리를 유지하면서 한 권으로 묶기 | 독립 작품의 학급 문집 |

합본책은 모든 작품이 하나의 줄거리로 이어지는 공동 서사와 다르다. 시스템이 다른 학생의 글을 하나의 문체로 자동 통일하지 않는다. 합본의 차례·표지·출처·판형은 자동 정리할 수 있지만 내용 수정 권한과 작성자 표시는 유지한다.

첫 파일럿은 ‘학급 공동책 1권’ 또는 ‘모둠별 짧은 책’으로 시작한다. 학생마다 별도의 장편·그림·음성을 만드는 운영은 교사 검수량과 비용을 확인한 뒤 확장한다. 페이지 수·그림 수·수업 차시는 교사가 시작 전에 설정하고, 초과 요청에는 범위와 추가 부담을 보여준다. 이 설정이 유료 생성 자동 승인으로 이어지지 않는다.

## 3. 학년군별 읽기–질문–쓰기 연결

| 학년군 | 읽기에서 출발할 질문 | 학생이 직접 할 일 | 지원 방식 | 초기 결과물 예시 |
|---|---|---|---|---|
| 1~2 | ‘이 인물은 무엇을 원했을까?’, ‘다른 방법이 있을까?’ | 장면 그림, 이야기 말하기, 순서 배열, 친구에게 설명 | 교사·짝 받아 적기, 큰 글자, 그림 카드, 짧은 공통 문장 틀 | 짝별 한 장면을 모은 학급책 |
| 3~4 | ‘이 선택을 바꾸면 다음 일도 달라질까?’ | 인물–문제–선택–결과를 합의하고 장면별 초안·수정 | 이야기 지도, 문장 연결 도움, 짝 피드백 | 모둠별 짧은 동화 |
| 5~6 | ‘다른 인물은 같은 사건을 어떻게 볼까?’, ‘이 결말은 설득력 있을까?’ | 독자·목적·관점·플롯 선택, 반응에 따른 내용 수정, 수정 이유 설명 | 원작 대조, 인과·관점 점검, 피드백 틀 | 대안 관점 동화·낭독극·문집 |

학년군은 고정 능력 등급이 아니다. 고학년도 구술·그림·대리 입력을 선택할 수 있다. 저학년의 그림·말·선택은 저작 기여로 기록한다. 교사가 받아 적은 문장은 ‘학생 구술, 교사 전사’로 표시하고 교사의 생각으로 자동 귀속하지 않는다.

원작을 참고할 때는 원문 인용·각색·새 창작을 구별한다. 저작권이 있는 현대 번역·삽화를 기존 작품이 오래됐다는 이유로 가져오지 않는다. 학생 작품에서 새로 만든 대사·사건을 원작 사실처럼 표시하지 않는다. 원작 사용 범위는 승인된 판본·권리 정책과 연결한다.

## 4. 핵심 사용자 흐름

### 4.1 교사 설정

1. 학급과 저작 모드, 독자, 수업목표, 수업 차시, 책의 최대 분량을 선택한다.
2. 참고한 작품 판본과 [학생 질문](02_reading_inquiry_curriculum.md)을 선택적으로 연결한다.
3. 학급·모둠·개인별 작업 단위를 배정하고 작성·검토 권한을 설정한다.
4. 그림·구술·종이·웹 중 사용할 표현 방식을 정한다. 학생 계정이 없어도 교사 관리 참여자로 시작한다.
5. 교사가 볼 검토 지점을 ‘줄거리 합의’, ‘초안 후 내용’, ‘내부 완성본’ 등 필요한 단계로 제한한다.

### 4.2 학생 창작

1. 각자 생각을 하나씩 제시한다. 말·그림도 인정한다.
2. 모둠이 독자·인물·문제·선택·결과를 합의한다.
3. 장면이나 페이지의 초안을 직접 만든다.
4. 친구의 질문을 받고 의미·인과·관점 중심으로 검토한다.
5. 필요한 경우 AI 제안을 요청한다. 제안은 별도 영역에 나타나고 원문은 유지된다.
6. 학생이 채택·거절·직접 수정을 결정하고 이유를 말하거나 남긴다.
7. 읽어 보며 마지막 내용 수정 후 맞춤법·판형을 정리한다.
8. 학급 내부 완성본으로 확정하고 서로 읽거나 [낭독극](04_readers_theater.md)으로 표현한다.

### 4.3 교사 검토 최소화

교사에게 모든 입력을 실시간으로 검수하도록 요구하지 않는다. 모둠의 선택된 초안, 서로 다른 결말, 미해결 내용 충돌, 내부 완성 요청을 검토 대기 목록에 모은다. 모둠별 대표 질문과 변경된 페이지를 먼저 보되, 교사는 필요하면 전체 원문에 접근할 수 있다.

본문이 확정되기 전에는 모든 페이지의 삽화·음성을 반복 제작하지 않는다. 텍스트·그림 원고의 내용을 먼저 정리하고 판형을 적용한다. 음성·AI 삽화는 선택 기능이며 이 PRD를 승인했다는 이유로 유료 호출을 실행하지 않는다.

## 5. 역할·협력·피드백

모둠 역할은 제안자, 기록자, 독자 역할의 질문자, 연결 점검자 등으로 구성하고 장면 또는 라운드마다 순환한다. 2~3명 모둠은 역할을 합칠 수 있다. 역할 이름은 사람의 능력·성별을 뜻하지 않는다.

- 먼저 개인의 생각을 내고, 이후 공동 결정을 한다.
- 기록자만 저자로 계산하지 않는다. 구술·그림·플롯 선택·질문·피드백·수정도 기여다.
- 개인별 기여 기록은 자동 입력량 순위가 아니라 학생·교사가 확인한 기여 종류와 연결 자료다.
- 학생의 제안을 모두 채택할 필요는 없지만 채택·보류한 이유를 대화할 수 있어야 한다.
- ‘이 인물이 왜 이렇게 했는지 이해되나요?’, ‘앞 장면과 이어지나요?’ 같은 소수의 피드백 틀을 제공한다.
- 동료 피드백이 문법 교정에만 머물지 않도록 내용 검토와 표기 검토를 분리한다.
- 소수 학생이 참여를 독점하면 역할 순환·작업 단위 축소·교사 중재로 조정한다. AI가 협력 점수를 자동 부여하지 않는다.

## 6. 기능 요구사항

‘필수/확장’은 공동저작 모듈 안의 구분이며, 제품 전체의 출시 순서는 [통합 계획](../main.md)을 따른다.

| ID | 모듈 내 구분 | 요구사항 |
|---|---|---|
| COAUTH-001 | 필수 | 학급 공동책·모둠책·합본책을 구분해 생성하고 각 모드의 공동 결정·작성 단위를 보여준다. |
| COAUTH-002 | 필수 | 모든 프로젝트·작업·페이지·기여·피드백은 학교·학급 범위를 가진다. 협력 교사는 명시적 권한을 받은 범위에만 접근한다. |
| COAUTH-003 | 필수 | 학생 Google 계정을 필수로 하지 않는다. 교사 관리 참여자·학급 내 제한 세션·종이 작업·교사 대리 입력을 지원한다. |
| COAUTH-004 | 필수 | 참고 작품의 승인 판본, 원작 장면, 학생 질문을 연결한다. 새 이야기와 원작의 관계를 기록하고 원작 인용과 창작을 구별한다. |
| COAUTH-005 | 필수 | 글·그림·구술 전사·종이 자료 등 표현 방식을 지원한다. 음성 인식·클라우드 전사를 필수로 하지 않는다. |
| COAUTH-006 | 필수 | 독자·목적·인물·문제·선택·결과를 간단한 기획표로 합의한다. 합본 모드는 공통 주제와 독자만 선택할 수 있다. |
| COAUTH-007 | 필수 | 장면·라운드별 역할 배정과 순환을 지원하고 변경 이력을 남긴다. 필기량·타자량만으로 역할·기여를 판정하지 않는다. |
| COAUTH-008 | 필수 | 페이지·장면별 편집 권한과 잠금을 제공한다. 다른 모둠 페이지는 읽기·피드백 범위만 별도로 허용한다. |
| COAUTH-009 | 필수 | 저장은 기준 버전을 검증한다. 같은 페이지의 오래된 초안 저장은 충돌 상태로 전환하며 조용히 최신 내용을 덮어쓰지 않는다. |
| COAUTH-010 | 필수 | 텍스트 변경은 새 버전으로 저장한다. 이전 버전 복원은 이력을 지우는 대신 복원 내용을 새 버전으로 만든다. |
| COAUTH-011 | 필수 | 학생 원문·사람의 수정·AI 제안을 구분한다. AI 제안은 원문과 별도 저장하고 자동 수락하지 않는다. |
| COAUTH-012 | 필수 | AI 제안의 전체·부분 수락, 거절, 직접 고쳐 쓰기를 지원한다. 수락한 범위와 사람의 결정 주체를 보존한다. |
| COAUTH-013 | 필수 | 동료 피드백은 질문·이해된 부분·헷갈린 부분으로 남기고 내용 수정에 연결할 수 있다. 피드백 수를 채워야 완료되는 조건은 없다. |
| COAUTH-014 | 필수 | 교사는 변경 페이지·미해결 충돌·완성 요청을 중심으로 검토한다. 모든 키 입력·모든 댓글을 승인해야 하는 구조를 만들지 않는다. |
| COAUTH-015 | 필수 | 텍스트와 학생 그림을 중심으로 기본 판형·차례·작성자·출처를 조립한다. 교사가 파일을 수작업으로 이어 붙이는 절차를 기본으로 두지 않는다. |
| COAUTH-016 | 필수 | 내부 완성본은 고정 버전이다. 이후 내용 수정은 새 편집본을 만들고 기존 완성본·인쇄본과 구별한다. |
| COAUTH-017 | 필수 | 기본 공유 범위는 학급 비공개다. 프로젝트 초안은 배정된 개인·모둠·교사만 접근한다. 원클릭 외부 공개·검색 노출·공개 파일 링크를 제공하지 않는다. |
| COAUTH-018 | 필수 | `assignment_id`는 프로젝트·단계·완성본에 선택적으로 연결한다. 개별 성적을 모둠 완성 여부로 자동 확정하지 않는다. |
| COAUTH-019 | 필수 | 평가 초안과 학생 자기성찰을 구분한다. 교사의 최종 평가·피드백 확정은 수동으로만 수행한다. |
| COAUTH-020 | 필수 | AI 꺼짐·미설정·오류·한도·비용 승인 없음에서도 기획·저작·피드백·수정·인쇄·학급 읽기가 가능하다. 자동 유료 대체는 없다. |
| COAUTH-021 | 확장 | AI는 막힘을 여는 질문, 모순 지적, 문장 대안, 편집 지원을 제안할 수 있다. 개인 학생의 전체 책을 자동 생성하는 기능은 기본 진입점에 두지 않는다. |
| COAUTH-022 | 확장 | 선택 AI 그림·음성은 승인된 본문 버전을 참조한다. 본문 수정 시 파생물의 불일치를 표시하고 유료 재생성을 자동 실행하지 않는다. |
| COAUTH-023 | 필수 | 사람의 기여·전사 주체·AI 사용·참고자료 정보를 작성자·기여자 화면과 완성본 제작 정보에 반영할 수 있다. 개인정보는 학급 공유 정책에 따라 최소화한다. |
| COAUTH-024 | 필수 | 교사·학생의 삭제·보관 요청 시 관련 초안·버전·파생 파일·피드백의 범위를 보여주고 상위 보관 정책을 적용한다. 로그를 원문 복구 창고로 사용하지 않는다. |

## 7. 페이지 잠금·버전·충돌 계약

초기 구현은 모든 학생의 자유로운 동시 편집보다 페이지·장면별 작업 소유와 버전 확인을 우선한다. 특정 라이브 협업 서비스 도입을 필수 조건으로 삼지 않는다.

1. **작업 배정:** 교사가 페이지·장면에 작성 가능한 개인·모둠을 지정한다.
2. **편집 시작:** 페이지의 현재 버전과 편집 잠금 상태를 확인한다. 잠금은 학급·사용자·페이지·만료 시점을 포함한다.
3. **잠금 보유:** 다른 사용자는 읽기·피드백을 할 수 있으나 같은 편집본을 덮어쓸 수 없다. 같은 모둠은 기록자를 바꾸며 잠금을 넘길 수 있다.
4. **잠금 만료·해제:** 연결 종료에 대비해 만료되는 임시 잠금으로 설계한다. 만료 시간은 접근성·학교 네트워크 검증 후 설정하고 교사가 강제 해제할 수 있다.
5. **저장:** `expected_revision`과 현재 버전이 같을 때만 저장한다. 검사와 저장은 하나의 원자적 처리로 보장한다.
6. **충돌:** 기존 서버 버전과 내 미저장 초안을 둘 다 보존해 비교한다. 사용자가 합치거나 다시 적용하도록 하며 AI 자동 병합으로 내용을 확정하지 않는다.
7. **복원:** 이전 버전 내용과 기여 정보를 확인한 뒤 새 버전으로 복원한다. 누가 무엇을 복원했는지 기록한다.
8. **파생물:** 내부 완성본·PDF·웹책·음성은 특정 본문 버전에 고정한다. 새 초안이 생겨도 이미 배부한 파일을 조용히 바꾸지 않는다.

공용 기기의 미저장 데이터는 기본적으로 세션 범위에 둔다. 학생 초안의 로컬 영구 저장을 기본 활성화하지 않는다. 연결이 끊겼을 때 저장된 것처럼 표시하지 않고, 허용된 복사·종이 대체·교사 인계를 안내한다. 개인정보가 포함된 임시 파일을 누구나 접근하는 다운로드 폴더에 자동 저장하지 않는다.

## 8. AI 제안의 처리 계약

AI는 학생의 저작 도구 중 하나이며 학습목표·연령·비용·데이터 처리 조건이 충족된 경우에만 켤 수 있다. 학생 원문을 외부로 전송하는 작업은 별도의 데이터 정책과 승인된 서비스 범위를 따라야 한다. 이 문서 작성 또는 일반 기능 승인은 유료 호출 승인이 아니다.

`학생 초안 → 도움 요청 → 제안 생성 또는 정적 도움 → 학생의 비교 → 수락·거절·직접 수정 → 새 사람 결정 버전`을 기본 흐름으로 한다.

- 제안 화면은 현재 원문과 제안의 차이를 보여준다.
- 제안이 인물·사건·결말을 바꾸면 의미 변화로 표시한다.
- 학생이 요청하지 않은 전체 문체 통일·줄거리 재작성은 자동 적용하지 않는다.
- 교사가 대신 수락할 경우 교사 결정으로 기록한다.
- AI가 쓴 문장을 학생이 수락했다는 사실과 학생이 처음부터 작성했다는 사실을 혼동하지 않는다.
- 그림 역시 학생 원화, 사람이 편집한 원화, AI 생성물을 구분한다. 원화는 변형 전 파일을 보존한다.
- AI 실패 시 원문·이미지·권한·판본이 손상되지 않아야 한다.
- 입력량 제한·비용 한도·오류가 생기면 유료 공급자나 상위 모델로 자동 전환하지 않는다.

## 9. 데이터와 권한

독립 `reading` 서비스는 Firebase Auth·Firestore·Cloud Storage를 목표 구조로 하며 서버·문서·파일 권한의 구체 계약은 [PRD 08](08_platform_architecture.md)을 따른다. 현재 로컬 프로토타입은 데이터 어댑터와 합성 참여자·창작 데모만 사용하며 실제 Firebase에는 연결하지 않는다. 이 문서에서는 서비스·DB·스토리지를 생성하거나 배포하지 않는다. 아래 엔터티는 논리적 데이터 계약이며 물리적 컬렉션·경로는 PRD 08에서 정한다.

모든 학생 공동저작 운영 문서는 `school_id`·`class_id`를 포함하고 관계의 학교·학급 일치를 검증한다. Firebase Auth로 확인된 신원에 대해 서버가 최신 membership의 소속·역할·활성 상태 및 모둠·페이지 작업 권한을 확인한다. Firestore·Storage Security Rules도 허용된 접근 범위를 검증하며 서버는 자체 권한 검증을 생략하지 않는다. 브라우저가 보낸 ID·로그인 성공·오래된 토큰 클레임만으로 접근을 허용하지 않는다.

로컬의 페이지 잠금·충돌·역할 전환은 UX 모의 상태다. 실제 다중 사용자 동시 편집의 원자적 저장, membership 변경에 따른 접근 철회, Security Rules 검증은 Firebase 연동 뒤 별도로 수행한다. 모의 시연을 실제 협업·보안 수용 기준의 통과로 기록하지 않는다.

| 엔터티 | 주요 필드 | 권한·보존 원칙 |
|---|---|---|
| coauthor_projects | id, school_id, class_id, mode, title, grade_band, audience, page_limit, assignment_id?, reference_edition_id?, status | 담당·협력 교사, 명시적으로 배정된 참여자 |
| project_members | school_id, class_id, project_id, profile_id, group_id?, role, active | 교사가 관리. 학생의 역할 변경으로 학교·학급 범위를 바꿀 수 없음 |
| story_plans | school_id, class_id, project_id, question_id?, purpose, character_goals, problem, choices, outcome, revision | 해당 프로젝트·모둠. 기획 원문은 업무 데이터로만 저장 |

| ai_suggestions | school_id, class_id, page_id, base_revision, suggestion_kind, proposed_content, status, decision_actor_id?, decision_revision? | 기존 초안과 별도. 승인된 서비스·비용·데이터 조건 충족 시만 생성 |

명단과 표시 이름은 교사 관리 정책을 따르고 외부 공개를 전제하지 않는다. 합본책의 작성자 표시도 학급 내부용 이름·별칭을 선택할 수 있다. 학생 글에 포함된 실명·생활사·민감한 표현을 분석 서비스나 오류 로그로 보내지 않는다. 저장·삭제 기간은 상위 문서의 정책 ID를 참조하고 ‘영구 보관’을 기본으로 가정하지 않는다.

## 11. 학습 관찰·운영 검증

개인 능력을 모둠의 예쁜 결과물로 대신 평가하지 않는다. 교사는 필요한 항목을 고르고 대표 장면·설명으로 확인한다. 다음은 검증 전 관찰 틀이다.

| 관찰 영역 | 확인할 증거 | 피할 대리 지표 |
|---|---|---|
| 구상 | 인물의 목표·선택·결과를 자기 말로 설명 | AI가 만든 줄거리의 길이 |
| 읽기와 연결 | 원작의 장면·질문에서 무엇을 바꿨는지 설명 | 원작 표현을 많이 복사한 양 |
| 협력 | 친구의 제안을 듣고 결정·피드백에 참여 | 타자 수·댓글 수·접속 시간 |
| 수정 | 독자 반응을 받아 바꾼 곳과 이유 설명 | AI 교정으로 맞춤법이 완벽해진 정도 |
| 자립성 | AI 없이 새로운 장면을 만들거나 수정 | 생성 버튼 사용량·완성책 권수 |

저학년 구술 받아쓰기는 1:1 도움이 필요해 교사 시간이 늘 수 있다. 학급 공동책·장면 단위 분담·짝 설명·교사 대표 전사로 운영을 시작하되, 지원이 줄어 학생의 목소리가 사라지지 않는지 확인한다. 전사·사진 정리·인쇄·검수 시간을 업무 절감 지표에서 제외하지 않는다.

## 13. 출처와 근거 한계

1. [IES/WWC, Teaching Elementary School Students to Be Effective Writers](https://ies.ed.gov/ncee/wwc/PracticeGuide/17?target=_blank), [공개 원문](https://ies.ed.gov/ncee/WWC/Docs/PracticeGuide/WWC_Elem_Writing_PG_Dec182018.pdf): 2012 발행·2018 개정. 목적에 맞는 쓰기과정 지도는 강한 근거, 필기·철자·문장·타자 유창성은 중간 근거, 쓰기 공동체 조성은 제한적 근거로 구분된다. AI 공동저작 자체의 효과 근거가 아니다.
2. [김채은·김세연, 2024, 디지털 기반 협동적 읽기–쓰기 수행 양상](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003059908): 실제 참여 유형에 표면적 공동 참여·한 사람의 고군분투·민주적 협업 등이 함께 나타남. 동시 편집 도구가 협력을 보장하지 않는다는 설계 근거다. 공개 초록에 표본 수는 제시되지 않았다.
3. [유승아, 2018, 초등 저학년 이야기글 쓰기 발달 종단 분석](https://www.kci.go.kr/kciportal/landing/article.kci?arti_id=ART002388587): 서울·전주 학생 349명의 3년 자료. 발달 단계에 따른 유창성과 글의 질의 역할 차이를 보고. 관찰 연구이며 모든 학생에게 같은 속도의 발달을 가정하지 않는다.
4. [NCTE, Draw a Story: Stepping from Pictures to Writing](https://www.readwritethink.org/classroom-resources/lesson-plans/draw-story-stepping?tab=2): K~1의 그림·구술·쓰기·책 만들기 지도안. 1:1 지원과 대기로 시간이 많이 들 수 있음을 명시한다. 효과 실험이 아니며 제시 시간표를 한국 수업의 표준으로 사용하지 않는다.
5. [Ye 외, Colin, 2024 제출·2025 개정](https://arxiv.org/abs/2405.06495): 진행자 검토, 질문·피드백, 그림·말로 이야기 연결을 돕는 인간–AI 공동 창작 시스템과 20명 사용자 연구. 소규모 시스템 평가로 장기 독립 쓰기·국내 전 학년 효과를 입증하지 않는다.

학급책·모둠책·합본책의 화면 구조, 페이지 잠금, 사람 기여 기록, AI 제안 승인 방식은 제품 설계다. ‘AI가 모두 쓰면 학습이 나빠진다’고 단정하기보다, 학습해야 할 구상·표현·수정 과정을 누가 수행했는지와 AI 없이 남는 역량을 검증한다.
