# GitHub · Vercel 배포 준비 기록

## 최종 로컬 릴리스 후보 · 2026-11-16

승인된 색연필 디자인, 내장 imagegen으로 제작한 주요 아이콘 16종, 서체, 책 가져오기·독서·질문·20종 활동지·책 공방·PDF·백업 기능을 하나의 로컬 Git 스냅샷으로 묶는다. 최신 전체 테스트는 **92/92 통과**, 프로덕션 빌드는 성공했다. 실제 브라우저와 PDF 검증은 [통합 검증 보고서](../artifacts/school-book-verification.md)에 기록했다.

`.env.local`, 서비스 계정 키, `.local`, 빌드 산출물, 기기 백업은 Git 대상에서 제외했다. 스테이지의 비밀키 패턴 검사에서도 일치 항목이 없었다. 아래 최초 조회 기록의 “stage·commit 미실행”은 그 조회 시점의 상태이며, 최신 로컬 Git 기록은 `git log -1`로 확인한다. GitHub push와 Vercel 배포는 아직 실행하지 않았다.

추가 읽기 조회에서 `jejuai`의 팀 ID는 `team_oK2XHUPJ4s9i5SUYtm1GlkMs`로 확인되었다. 두 MCP 연결 모두 `get_team`이 403으로 거절되어 실제 요금제·청구 기간·잔여량·중지 설정은 여전히 확인되지 않았다. 로컬 CLI 인증과 저장소 쓰기 권한은 유효하다. **이는 자동 승인 검토의 거절이 아니라 서비스 연결의 팀 접근 오류**다. 사용자의 별도 과금 사전 승인 지침에 따라 요금 불확실성이 있는 외부 배포는 승인 전 실행하지 않는다.

확인일: 2026-11-16. 현재 작업 위치는 `C:\Users\na\Desktop\vibe2\reading`이다. 이 문서는 연결된 서비스의 읽기 전용 조회와 로컬 소스 검토 결과이며 **배포 완료 기록이 아니다**. 원격 저장소 생성, push, Vercel 프로젝트 연결·생성, 환경변수 업로드, 배포, 도메인·요금 설정 변경은 실행하지 않았다. 이후 사용자 지시에 따른 로컬 Git 초기화와 원격 주소 지정만 완료했다.

**사용자 지정 대상 갱신:** 사용자가 `https://github.com/jejuailabs/reading.git`와 `main` 브랜치를 명시했다. 직접 조회 결과 공개 저장소, 기본 브랜치 `main`, 보고된 크기 0KB, 저장소 ID `1459317202`이다. MCP의 `funjeju` 연결에는 push 권한이 없지만, 이후 확인한 **로컬 GitHub CLI의 활성 계정 `jejuailabs`에는 해당 저장소의 admin/maintain/pull/push/triage 권한이 모두 있다.** 저장소 브랜치 목록과 저장소 webhook 목록은 각각 빈 배열이었다. GitHub App 연동은 저장소 webhook 목록만으로 배제할 수 없으므로 자동 배포 가능성은 별도로 확인한다.

최초 계정 목록에서 확인한 `funjeju` 소유 4개 저장소는 대상에서 제외한다. **실제 GitHub 대상은 사용자가 지정한 [jejuailabs/reading](https://github.com/jejuailabs/reading)이다.** 이 저장소 URL을 사용한 Vercel MCP 필터 조회는 `ourclass` scope의 동일한 403이었다. 로컬 Vercel CLI는 별도 인증으로 읽기 조회에 성공했다.

이름이 유사한 기존 `jejuai/aireadingbook`은 `https://aireadingbook.vercel.app`, 프로젝트 ID `prj_xJh2ENQYDNAUh7F74B3IoGEdr8uy`, 2026-11-04 생성, Next.js, 루트 `.`, Node 26.x로 조회되었다. **기존 프로젝트이며 `jejuailabs/reading`과의 Git 연결은 확인하지 못했으므로 이번 앱의 대상으로 지정하지 않았다.** `jejuai` 목록에는 기존 homework도 보였으나 해당 프로젝트를 inspect하거나 수정하지 않았다. 새 저장소를 만들거나 다른 앱을 덮어쓰지 않는다.

Vercel의 403은 서비스 연결의 팀 접근 오류다. 실행 승인 자동 검토에서 거절된 것이 아니다. 해당 팀이 맞으면 `authorize_team_access` 도구가 제공하는 10분짜리 일회성 승인 링크로 기존 연결의 팀 접근을 승인할 수 있다. 현재는 대상 팀이 미확정이므로 링크 생성이나 계정 설정 변경도 하지 않았다.

로컬 CLI 첫 조회는 sandbox의 네트워크 EACCES로 실패했다. 같은 읽기 전용 명령을 허용된 네트워크 실행으로 확인한 뒤 정상 인증임을 확인했으므로, 최초 오류를 “계정 만료”로 보고하지 않는다. 사용한 명령은 `Get-Command git,gh,vercel`, 비밀 행을 제외한 `gh auth status`, 지정 저장소 메타데이터/브랜치/webhook의 GET, `vercel whoami`, `vercel teams ls`, 명시적 scope의 `vercel project ls/inspect`와 도움말이다. 토큰 파일·`.env.local`·서비스 계정 JSON은 읽지 않았고, npx 설치·계정 전환·연결·배포 명령도 실행하지 않았다. CLI 48.10.11 도움말에는 일반 `vercel api` 기능이 없어 이 경로로 요금 정보를 조회하지 않았다.

로컬 Git 변경은 `reading` 절대 경로와 `.git` 부재를 확인한 뒤 수행했다. `git branch --show-current`는 `main`, `git remote -v`의 fetch/push 주소는 모두 지정 URL이었다. `git diff --cached --name-only`는 비어 있어 stage된 파일이 없다. 이 작업은 로컬 메타데이터 변경이며 GitHub로 전송하거나 Vercel 빌드를 시작하지 않았다. 설치된 Vercel CLI의 `teams --help`에는 add/invite/list/switch만 있으며 `teams inspect`나 요금 조회 명령을 추측 실행하지 않았다.

## 2. 비용 확인과 승인 범위

사용자의 상시 지침에 따라, 별도 과금이 발생하거나 과금 여부가 불확실한 작업은 서비스·목적·예상액·상한·기간·초과/갱신 조건을 설명하고 명시적 승인을 받아야 한다. 기존 API 키, 이미 가입한 플랜, 소액 또는 무료 크레딧은 별도 승인을 대신하지 않는다. 로컬 텍스트·낭독·삽화 검증의 승인 범위가 Vercel 호스팅이나 공개 서비스의 AI 호출 승인으로 확장되지는 않는다.

GitHub 저장소는 공개이고 조회 당시 브랜치가 없다. GitHub Actions 사용량·청구 조건과 GitHub App의 자동 배포 연결은 이번 조회에서 검증하지 않았다. 저장소에 push하면 연결된 Vercel이 자동 빌드할 수 있으므로, **push도 배포와 비용을 유발할 수 있는 단계로 다룬다**. [Vercel Git 연동 문서](https://vercel.com/docs/git)

## 3. 현재 배포할 앱의 성격

현재 완성 범위는 **브라우저에 작업을 저장하는 온책읽기 프로토타입**이다. 웹주소가 생겨도 아래 한계가 자동으로 해결되지는 않는다.

| 기능 | 배포 후 기대할 수 있는 범위 | 운영 서비스와의 차이 |
| --- | --- | --- |
| 읽기·샘플 낭독 | 배포에 포함한 고전 본문·정적 삽화·기존 MP3를 이용한다. | MP3 재생은 새 TTS 추론이 아니지만 전송량은 호스팅 사용량이다. |
| 원고·그림·PDF 가져오기 | 브라우저에서 처리하고 그 브라우저의 IndexedDB에 저장한다. | 다른 기기·브라우저·URL에서 자동 동기화되지 않는다. |
| 책 공방·개인/팀 작업 | 직접 집필, 페이지 편집, 실제 업로드 그림, 같은 기기의 순차 협업, 고정 판본 보관을 한다. | 실제 다중 사용자 실시간 공동 편집·서버 계정별 보관은 없다. |

Preview 주소에서 작성한 데이터는 Production 주소에 자동으로 이어지지 않는다. 주소가 달라지기 전에 `/guide`에서 전체 JSON 백업을 받고, 지원되는 형식으로 새 주소에서 복원하는 흐름을 확인한다. PDF는 읽기용 결과물이고 JSON은 편집 데이터 백업이다. 브라우저 데이터 삭제·저장소 부족 가능성도 계속 존재한다.

## 4. AI 경로의 배포 경계

읽은 코드 기준으로 `src/lib/server/reading-ai-runtime.ts`와 `src/lib/server/book-image-runtime.ts`는 `NODE_ENV !== "development"` 또는 `VERCEL` 환경이면 요청을 거절한다. 텍스트 파일럿은 추가로 `http://127.0.0.1:3100` 또는 `http://localhost:3100`, 요청 출처, 승인 유효기간, 세션, 비용 원장을 확인한다. 이미지 파일럿도 별도 승인·세션·비용 원장 경로를 가진다.

따라서 **현재 코드를 Vercel에 배포해도 유료 텍스트·이미지 생성 API가 운영용으로 활성화되는 것은 아니다.** `PAID_OPERATIONS_ENABLED=false` 같은 설명용 플래그만을 비용 차단의 유일한 근거로 삼지 말고 실제 서버 검증을 유지한다. 로컬 `.local` 파일 원장은 여러 서버 인스턴스가 사용하는 운영 예산 장부로 재사용할 수 없다.

공개 환경에서 AI를 제공하려면 실제 인증, 서버 권한, 중앙의 원자적 예산 예약·중복 방지·속도 제한, 운영 보관 정책, 명시적 비용 승인, 장애/불명확 결과 처리, 해당 도메인 보안 정책을 별도 설계·검증해야 한다. 이번 배포 준비에서 이 제한을 해제하거나 로컬 승인 시각·세션 비밀·OpenAI 키를 Vercel에 올리지 않는다. 미리 생성한 정적 음원·이미지는 이 런타임 API와 구분한다.

## 5. Git 제외 규칙 검토

`.gitignore`와 비밀값이 없는 `.env.example`만 읽었으며 `.env.local`과 서비스 계정 JSON 내용은 읽지 않았다.

| 대상 | 현재 규칙 | 판단 / 배포 전 조치 |
| --- | --- | --- |
| `.env.local` 및 환경 파일 | `.env*`, 예외 `!.env.example` | 제외된다. 예제에는 빈 비밀값과 꺼진 기본값이 있으며 실제 키가 없다. 로컬 env를 통째로 배포하지 않는다. |
| Firebase 서비스 계정 | `*firebase-adminsdk*.json`, `service-account*.json` | 이 이름 패턴은 제외된다. 다른 이름으로 저장한 자격증명은 자동 보장되지 않으므로 최종 파일 목록을 별도 확인한다. |
| 로컬 비용 원장 | `/.local/` | 텍스트·삽화 원장, 잠금·캐시를 저장하는 이 경로는 제외된다. |
| 의존성·빌드 결과 | `node_modules/`, `.npm-cache/`, `.next/`, `out/`, `dist/`, `*.tsbuildinfo`, `coverage/` | 제외된다. 재현 가능한 소스와 lockfile을 이용한다. |
| Vercel 로컬 설정 | `.vercel/` | 제외된다. 현재 해당 폴더도 없다. |
| 로그 | `*.log` | 제외된다. |
| 스크린샷·디자인 원본 | `/artifacts/**/*.png`, `*.jpg`, `*.jpeg`, `*.webp`, `*.pdf`에 해당하는 개별 패턴 추가 | 원본을 로컬에 보존하면서 이미지·검증 PDF는 Git 대상에서 제외했다. 출처·제작 기록 Markdown/JSON은 유지한다. |
| 출력 PDF·임시 파일 | `/output/`, `/tmp/` 추가 | `output/pdf`, `tmp/pdfs`의 로컬 검증 결과가 배포 소스에 섞이지 않도록 제외했다. |
| 실제 서비스 정적 파일 | `public/` | 의도적으로 필요한 한글 글꼴·PDF worker·삽화·오디오만 포함한다. `/public` 전체를 일괄 제외하면 앱이 깨진다. |

사용자 지정 저장소가 전달된 뒤 루트 담당자의 지시에 따라 위 산출물 제외 규칙을 `.gitignore`에 추가했다. `public`의 실제 콘텐츠·글꼴·음원·PDF worker는 제외하지 않았다. 최초 commit 전에 staged 파일 목록을 확인해야 한다. `.gitignore`는 이미 추적 중인 파일을 제거하지 않으며, GitHub 연동과 CLI 직접 업로드의 업로드 범위를 동일하다고 가정하지 않는다. CLI 경로를 택한다면 `.vercelignore` 또는 업로드 목록도 별도로 검토한다.

검토 시점의 `public` 파일은 123개, 총 49,586,595bytes(약 49.6MB)였다. 이는 파일 합계이며 첫 화면 전송량·실제 청구 전송량·빌드 결과 크기와 다르다. 영상/음원 전체를 매번 내려받는다고 가정하지도, 정적 파일이라 호스팅 비용이 없다고 가정하지도 않는다.

## 6. 대상 확정 후 실행 순서

1. 확정된 `jejuailabs/reading`의 `main`을 사용하되 기존 원격 이력·루트 디렉터리와 쓰기 권한을 확인한다. 기존 원격 코드와 로컬 작업 차이를 검토하고 기존 이력을 보존한다. 새 저장소 생성·강제 push·기존 앱 덮어쓰기는 포함하지 않는다.
2. Vercel 팀·프로젝트·Git 연결·Production 브랜치·root directory·환경을 읽어서 확인한다. 위 목록의 다른 저장소나 `ourclass`를 자동 선택하지 않는다.
3. 실제 플랜·잔여량·사용량·과금/중지 조건과 원하는 공개 범위를 제시한다. 확인된 무료 범위인지 또는 유료 승인 대상인지 결정하고 사용자 상시 비용 지침을 충족한다.
4. 비밀값·원장·스크린샷·출력물을 배포 대상에서 정리한다. `package-lock.json`, `src`, 필요한 `public` 자산, `scripts/sync-pdf-worker.mjs` 등 빌드 입력은 보존한다.
5. 로컬에서 `npm run typecheck`, `npm test`, `npm run build`를 통과한 동일 소스를 기준으로 커밋한다. 최근 검사 결과와 실제 배포할 커밋이 다르면 그 차이에 필요한 검증을 한다.
6. 기존 Next.js 구성을 사용한다. 빌드 명령은 `npm run build`이며 `prebuild`가 로컬 패키지의 PDF worker를 `public`에 준비한다. 현재 `npm run dev`/`start`의 `127.0.0.1:3100`은 로컬용이므로 Vercel에 상시 개발 서버로 올리지 않는다.
7. 승인 범위 안에서 GitHub에 소스를 반영하고 해당 커밋의 Vercel 배포를 확인한다. Git 연동이 이미 있으면 push 자체로 자동 배포가 시작될 수 있음을 앞 단계에서 확인한다.
8. 배포 주소에서 한글 글꼴·정적 그림·음원·PDF worker 로딩, 가져오기, 기기 저장/백업/복원, 추천 책 수업 시작, 책 공방, 전권 PDF, 모바일 표시를 확인한다. 외부 유료 AI 호출은 이 검사에 포함하지 않는다.
9. 배포 URL·커밋·환경·검사 결과·알려진 한계·비용 조건을 기록하고 사용자에게 전달한다. 실제 학교 계정 운영, 공개 학생 작품, 공동 편집, 운영 AI가 완료되었다고 표시하지 않는다.
