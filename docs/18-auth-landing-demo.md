# 서비스 소개 · Google 로그인 · 체험 교실

작성일: 2026-11-16. 이번 변경의 사용자 안내와 운영 설정을 함께 기록한다.

**상태:** 설명형 랜딩페이지, Google 인증과 서버 세션, 체험/계정 작업 공간 분리를 구현했다. 승인된 업데이트 `7b66690`은 2026-11-16 16:04 KST에 배포했으나 빌드 `READY` 이후 서버에서 `ERR_REQUIRE_ESM`과 HTTP 500이 발생했다. 새 빌드 없는 Instant Rollback으로 이전 소스 `6aa8393`을 복구하고 첫 화면을 확인했다. 패키지 버전을 유지하는 번들 설정 수정 후 **106개 테스트·프로덕션 빌드·오프라인 프로덕션 실행 검사 9개가 통과**했다. 수정본의 추가 배포 1회는 아직 승인·실행하지 않았다. 로컬에서 실제 Google 로그인 페이지 진입은 확인했지만 실제 계정 로그인 완료·재접속·로그아웃은 검증하지 않았다. 아래 기능 안내는 수정본 소스 기준이며 현재 공개 사이트와 구분한다.

## 1. 어디서 시작하나요?

서비스 첫 화면은 온책읽기의 활용 방법을 한 페이지에서 안내한다. 책 찾기와 가져오기, 읽고 듣기, 학생 자신의 질문, 기록지와 PDF, 낭독극, 책 만들기의 관계를 살펴볼 수 있다. 모든 활동을 차례대로 끝내야 하는 것은 아니다.

페이지 맨 위와 맨 아래의 **Google로 시작하기**로 로그인한다. 먼저 기능을 살펴보려면 **로그인 없이 체험하기**를 선택한다. 기존 이야기 여정과 서재 화면은 체험 교실에 그대로 남아 있다.

| 공간 | 주소 | 사용 방법 |
|---|---|---|
| 서비스 소개 | `/` | 전체 활용법을 읽고 로그인 또는 체험을 선택한다. |
| 로그인 | `/login` | Google 계정으로 로그인한다. |
| 체험 교실 | `/demo` | 샘플 책과 체험 안내를 따라 자유롭게 활동한다. |
| 내 작업 공간 | `/app` | 로그인한 계정으로 독서·질문·저작 작업을 이어간다. |

서재·리더·공방의 사용법은 두 공간에서 같다. 예를 들어 체험 서재는 `/demo/library`, 내 서재는 `/app/library`다. 왼쪽 메뉴의 **서비스 소개**를 누르면 처음 안내 페이지로 돌아간다.

예전에 보관한 `/library`, `/reader/{책ID}` 등의 링크는 해당 체험 화면으로 연결된다. 내 계정의 작업을 열 때는 로그인한 뒤 내 공간의 메뉴를 이용한다.

## 2. Google로 로그인하기

1. 서비스 소개의 위쪽 또는 아래쪽에서 **Google로 시작하기**를 누른다.
2. Google 창에서 사용할 계정을 선택한다. 학교에서 지정한 계정이 있다면 해당 계정을 사용한다.
3. 인증이 끝나면 **내 작업 공간**으로 이동한다. 로그인 화면으로 오기 전에 열려던 허용된 작업 화면이 있으면 그 화면으로 돌아간다.
4. 왼쪽 아래에서 내 이름과 계정 상태를 확인한다.

이미 로그인했다면 버튼은 **내 작업 공간**으로 표시된다. 비밀번호를 이 서비스 화면에 직접 입력하는 방식은 제공하지 않는다.

로그인은 최대 5일 동안 유지되도록 구성한다. 만료되거나 계정 상태 확인에 실패하면 다시 로그인해야 한다. 공유 기기에서는 작업을 마친 뒤 왼쪽 아래의 **로그아웃**을 누른다. 로그아웃은 현재 서비스의 로그인 상태를 끝내며, 작성한 책과 기록을 삭제하는 동작은 아니다.

### 문제가 생겼을 때

| 상황 | 할 일 |
|---|---|
| Google 창이 뜨지 않는다 | 브라우저의 팝업 차단 여부를 확인하고 로그인 버튼을 다시 누른다. |
| 계정 선택 창을 닫았다 | 작업은 로그인되지 않은 상태로 남는다. 필요할 때 다시 누른다. |
| 학교 계정에서 허용하지 않는다고 나온다 | 학교 계정 관리 정책을 확인한다. 다른 사람의 계정을 공유하지 않는다. |
| 로그인이 준비되지 않았다는 안내가 나온다 | 운영자가 인증 설정과 배포 상태를 확인해야 한다. 체험 교실은 별도로 이용할 수 있다. |
| 로그인 뒤 다른 기기에서 작업이 보이지 않는다 | 현재 작업은 작성한 기기에 보관된다. Google 로그인만으로 여러 기기 사이에 자동 복사되지는 않는다. |
| 로그아웃 실패 안내가 나온다 | 연결을 확인한 뒤 다시 누른다. 안내가 남아 있으면 로그아웃이 완료된 것으로 보지 않는다. |

## 3. 체험 교실에서 직접 해보기

체험 교실 위쪽의 **온책읽기 체험 교실**에서 다섯 가지 활동을 바로 열 수 있다. 다른 화면에서는 **체험 안내 펼치기**로 다시 볼 수 있다.

1. **이야기 읽고 듣기:** 「흥부와 놀부」를 펼친다. 글과 그림을 보고, 저장된 낭독을 재생하고, 책갈피를 꽂아 본다.
2. **나만의 질문 남기기:** 같은 책에서 궁금해진 점을 자신의 말로 남긴다. 체험 안내를 누르는 것만으로 질문이나 학습 성취가 자동 기록되지는 않는다.
3. **기록지와 PDF 만들기:** 같은 책의 기록지에서 필요한 양식을 고른다. 한 문항씩 답하고 빈 양식 또는 작성한 내용을 PDF로 내려받는다.
4. **배역을 나눠 읽기:** 「바람 우체국」 샘플 대본을 열고 배역별로 읽거나 대본을 인쇄한다. 이 대본은 「흥부와 놀부」를 자동으로 각색한 결과가 아니다.
5. **우리 책 한 권 만들기:** 주제·책 종류·장수 등을 정하고 장면을 작성한다. 그림을 고르고 검토한 뒤 완성본으로 엮는다.

서재에는 전래동화 5편과 이솝우화 5편 외에 창작 샘플도 있다. 「흥부와 놀부」 대신 다른 책으로 시작해도 된다. 가져온 원고, 종이책 서지, 텍스트 PDF, 페이지 그림 등은 기존 책 가져오기 흐름을 이용한다. 입력 형태별로 본문을 파악할 수 있는 범위는 [학교 책 수업 매뉴얼](16_school_book_manual.md)을 참고한다.

체험 교실의 왼쪽 아래 **체험할 역할**에서는 학생·선생님·관리자 화면을 바꿔 볼 수 있다. 이는 실제 계정에 교사나 관리자 권한을 주는 기능이 아니다. 관리자 체험의 학교와 명부는 가상 예시다. 실제 학생 정보는 체험 자료로 입력하지 않는다.

## 4. 체험과 내 작업은 어떻게 보관되나요?

| 항목 | 체험 교실 | 내 작업 공간 |
|---|---|---|
| 로그인 | 필요 없음 | Google 로그인 필요 |
| 역할 선택 | 체험용 학생·선생님·관리자 선택 가능 | 서버가 확인한 권한만 적용 |
| 저장 | 현재 브라우저의 체험 공간 | 현재 브라우저의 계정별 공간 |
| 기존 작업 | 이전 버전에서 만든 체험 자료 유지 | 다른 계정과 분리해 시작 |
| 기기 간 동기화 | 제공하지 않음 | 제공하지 않음 |
| 팀 작업 | 한 기기에서 순서대로 작성 | 한 기기에서 순서대로 작성 |

로그인해도 체험 기록이 내 계정으로 자동 이동하지 않는다. 필요한 자료는 체험 공간에서 백업하고 내 공간에서 내용을 확인해 가져오는 방식을 사용한다. 백업 복원은 합치기가 아니라 선택한 저장소의 교체이므로 현재 작업을 먼저 보관한다. 계정 공간의 백업과 복원은 현재 계정에만 적용되도록 구성하며, 체험 자료나 다른 계정의 저장소를 함께 바꾸지 않는다.

브라우저 데이터를 지우거나 기기를 바꾸면 작업을 잃을 수 있다. **사용 안내 · 백업**에서 전체 JSON 백업을 보관한다. PDF는 읽고 인쇄하기 위한 결과물이며, 이후 글과 장면을 다시 편집하려면 JSON 자료도 필요하다.

계정별 기기 저장은 학교 서버의 학생 기록 관리나 기기 자체의 보안 격리를 대신하지 않는다. 공유 기기에서는 학교가 정한 브라우저 프로필·기기 관리 방법을 함께 사용한다.

## 5. 실제 교사·관리자 권한

처음 Google로 로그인한 계정은 일반 회원으로 시작한다. 계정 종류를 화면에서 고르는 것만으로 교사·관리자가 되지 않는다.

| 계정 역할 | 가능한 공간 |
|---|---|
| 일반 회원·학생 | 내 서재, 읽기·듣기, 자기 질문, 기록지, 책 공방, 내 작품 |
| 승인된 교사 | 위 기능과 수업 구성 |
| 승인된 관리자 | 위 기능과 운영 상태 화면 |

현재 운영 상태 화면은 이 기기에 저장한 작업의 집계와 연결 상태를 보여준다. 학교 전체 명부·다른 학생의 학습 내용·여러 기기에서 수집한 통계를 조회하는 관리 시스템은 이번 로그인 변경의 완료 범위가 아니다.

## 6. 이번 변경으로 자동으로 켜지지 않는 기능

- 새로운 AI 질문·구성안·삽화 생성: 운영 환경에서는 기존 비활성 상태를 유지한다. 버튼과 화면의 실제 안내를 따른다.
- 샘플 낭독 재생: 이미 저장된 음성을 사용한다. 재생할 때마다 새 음성을 생성하는 방식이 아니다.
- 클라우드 저장·실시간 공동 편집·학교별 명부 연동: Google 로그인과 별도 기능이며 이번에 자동으로 활성화하지 않는다.
- homework: 기존 프로젝트의 코드·데이터·인증·설정·배포를 변경하지 않는다.

## 7. 운영자 설정

이하 내용은 배포와 인증을 설정하는 운영자를 위한 안내다. 사용자는 이 환경변수를 입력할 필요가 없다.

### 환경변수

실제 값은 로컬에서는 Git에서 제외된 `.env.local`, 운영에서는 reading Vercel 프로젝트의 환경변수에 둔다. 비밀값을 문서·커밋·클라이언트 코드에 붙여 넣지 않는다.

| 변수 | 용도 |
|---|---|
| `NEXT_PUBLIC_FIREBASE_API_KEY` | Firebase 웹 앱 공개 설정 |
| `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN` | Google 인증을 처리하는 Firebase 인증 도메인 |
| `NEXT_PUBLIC_FIREBASE_PROJECT_ID` | 웹 앱이 사용할 Firebase 프로젝트 |
| `NEXT_PUBLIC_FIREBASE_APP_ID` | Firebase 웹 앱 식별자 |
| `FIREBASE_ADMIN_PROJECT_ID` | 서버 인증 검증 대상 프로젝트 |
| `FIREBASE_ADMIN_CLIENT_EMAIL` | 서버 전용 서비스 계정 식별자 |
| `FIREBASE_ADMIN_PRIVATE_KEY` | 서버 전용 서비스 계정 비밀키 |
| `READING_ALLOWED_FIREBASE_PROJECT_ID` | reading이 연결해도 되는 프로젝트를 명시하는 허용값 |
| `READING_AUTH_ENABLED` | 설정과 승인 범위를 확인한 뒤 인증 실행을 켜는 값 |
| `READING_APP_ORIGIN` | 실제 서비스의 HTTPS 출처. 로그인 요청의 출처 검사에 사용 |

공개 프로젝트 ID·Admin 프로젝트 ID·허용 프로젝트 ID는 일치해야 한다. 공개 설정의 `NEXT_PUBLIC_` 접두사를 서버 비밀키에 붙이지 않는다. `STORAGE_BUCKET`, `MESSAGING_SENDER_ID`, `MEASUREMENT_ID` 설정 보유가 Storage·메시지·Analytics 연결을 의미하지는 않는다. 인증 외 서비스는 별도 검토 없이 켜지 않는다.

2026-11-16 업데이트 준비에서 위 필수 10개와 웹 설정의 `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`, `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID`를 합한 12개 변수를 **reading Production**에 설치했다. 비밀키는 서버 전용 sensitive 값으로 등록했다. 이 설정 작업은 Firestore·Storage·Analytics 초기화나 데이터 저장을 실행하지 않는다.

### Google 인증과 배포 준비

1. 제공된 Firebase 프로젝트와 웹 앱이 의도한 대상인지 확인한다. 다른 앱이 함께 사용하는 프로젝트일 가능성을 고려한다.
2. 기존 Google 로그인 제공자와 승인 도메인을 확인한다. reading 운영 도메인만 필요한 범위로 추가하며 기존 항목은 보존한다.
3. Firebase의 실제 요금제·사용량·추가 과금 여부와 이번 사용 범위를 확인한다. 별도 과금이 발생하거나 불확실하면 사용자에게 비용과 조건을 설명하고 승인받은 뒤 해당 원격 작업을 실행한다.
4. reading 전용 환경변수를 설정한다. `READING_AUTH_ENABLED=true`는 실제 활성화 단계의 값이며 예제 파일을 복사한 것만으로 켜지지 않게 한다.
5. 로컬 검사와 검증 결과를 준비한다. 추가 Vercel 배포는 기존 최초 배포 1회의 승인과 구분해 처리한다.
6. 배포 후 실제 운영 주소에서 Google 계정 선택 → 로그인 → 계정별 공간 → 새로고침 → 로그아웃을 확인한다. 성공한 범위만 완료로 기록한다.

### 세션과 접근 검사

- Google 인증 결과를 서버에서 검증한 뒤 `reading_session` HttpOnly 쿠키를 만든다. 유효기간은 최대 5일이다.
- 운영 쿠키는 HTTPS 전용이며 브라우저 JavaScript에서 직접 읽을 수 없도록 한다. 인증 응답은 공유 캐시에 저장하지 않는다.
- 로그인·로그아웃 요청의 출처와 요청 형식을 검사한다. 임의의 외부 주소로 로그인 완료 후 이동시키지 않는다.
- `/app/*`와 교사·관리자 공간은 서버가 확인한 세션과 권한으로 접근한다. 클라이언트의 역할 선택값과 브라우저 저장값을 권한 증거로 사용하지 않는다.
- 신뢰하는 역할 값은 앱 전용 `reading_role`이며, 값이 없거나 올바르지 않으면 일반 회원으로 취급한다. 다른 앱이 쓰는 `role` 등의 속성을 그대로 권한으로 받아들이지 않는다.
- 로그아웃은 reading의 세션 쿠키를 지운다. 공유 Firebase 프로젝트의 모든 토큰을 일괄 취소하거나 다른 서비스의 사용자를 로그아웃시키지 않는다.

운영자가 역할을 부여할 때도 기존 사용자 속성을 지우고 덮어쓰지 않아야 한다. 이번 변경에는 학교 소속 승인이나 사용자 역할을 일괄 부여하는 관리 도구가 포함되지 않는다.

## 8. 검증과 문서의 시점

수정본은 **106개 테스트·프로덕션 빌드·오프라인 프로덕션 실행 검사 9개를 통과**했다. 로컬에서 실제 Google 로그인 페이지 진입도 확인했다. 테스트의 모의 인증 결과와 사용자의 실제 Google 로그인 성공은 구분한다. 사용자 자격증명을 입력하거나 실제 로그인 완료를 검증하지 않았다.

승인된 업데이트 배포 `dpl_CGQKE6wnVVwUWfwMtcsziVDSPrW4`는 빌드 완료 뒤 런타임에서 실패했다. `firebase-admin@14.5.1 → jwks-rsa@4.1.0 → jose@6.2.17`의 CommonJS/ESM 로딩 경계에서 발생한 오류로, 이전 `dpl_Ex4hkhbqeHiGrSxrxrrSiUicgpvL`을 Instant Rollback으로 복구했다. 관련 상위 저장소의 보고는 [Firebase Admin #3181](https://github.com/firebase/firebase-admin-node/issues/3181), [node-jwks-rsa #507](https://github.com/auth0/node-jwks-rsa/issues/507)에 있다. 이 프로젝트의 실제 장애 판단은 운영 로그와 로컬 재현을 근거로 했다.

수정은 의존성 버전을 변경하지 않고 Next `transpilePackages`에 `firebase-admin`, `jwks-rsa`, `jose`를 넣어 번들에서 로딩 경계를 처리하는 방식이다. 아래 순서로 빌드 후 `--no-experimental-require-module` 조건의 로컬 프로덕션 서버를 검사한다. 시험용 키를 실행 중 생성하며 실제 인증 호출이나 사용자 생성은 하지 않는다. 잘못된 토큰 요청도 Admin 초기화까지 거친 뒤 400으로 거부되는지 확인한다.

```powershell
npm test
npm run build
npm run test:auth-runtime
```

이번에 승인된 업데이트 1회는 이미 실행했다. 추가 빌드·배포 비용 범위는 별도 승인을 받아야 하며, 준비된 수정본은 아직 재배포하지 않았다. 상세 실행 결과는 [검증 기록](../artifacts/auth-landing-verification.md)에 둔다.

다음 항목은 출시 검증의 전체 수용 기준이다. 로컬·모의 검사와 실제 운영 계정 검증을 구분하며 체크리스트 자체를 전체 통과 기록으로 해석하지 않는다.

- 랜딩페이지의 최상단·최하단 로그인, 체험 진입, 모바일·다크·언어 전환.
- 체험 메뉴 이동이 `/demo/*` 안에, 계정 메뉴 이동이 `/app/*` 안에 유지되는지.
- Google 팝업 취소·차단·인증 실패가 성공으로 표시되지 않는지.
- 로그인하지 않은 `/app/*` 접근과 일반 회원의 교사·관리자 경로 접근 차단.
- 새로고침 후 세션 유지, 로그아웃 후 보호 화면 재접근 차단.
- 계정 A·계정 B·체험 사이의 읽기 기록·공방·기록지·백업 분리.
- 예전 체험 자료 유지와 계정 전환 때 마지막 저장 누락 여부.
- 서버 전용 인증 자료가 Git·정적 자산·브라우저 번들에 포함되지 않는지.

이전 버전 문서의 `/library` 경로, ‘화면 미리보기’ 역할 선택, ‘Google 로그인 미구현’ 등의 설명은 당시 상태를 나타낸다. 이번 새 버전에서는 본 문서의 `/demo/*`와 `/app/*` 구분을 적용하며, [기존 수업 매뉴얼](16_school_book_manual.md)의 개별 활동 사용법은 계속 참고할 수 있다. 반면 기존 PRD에 적힌 학교 명부·클라우드 저장·실시간 협업은 여전히 별도 구현 목표다. 문서의 설명 변경만으로 운영 연결이나 실제 Google 로그인 검증이 완료되는 것은 아니다.
