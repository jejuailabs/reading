# 읽기·질문·탐구 교육과정 PRD

- 문서 ID: PRD-02
- 상태: 설계·로컬 프로토타입 착수. 기능 구현·교육 효과 검증·서비스 개설을 완료했다는 뜻이 아니다.
- 기준일: 2026-11-16
- 적용 대상: 국내 초등 1~6학년, 담임·국어 수업 교사, 사서교사와 협력 교사
- 상위 문서: [통합 계획](../main.md)
- 연계 문서: [낭독극](04_readers_theater.md), [학생 공동저작](06_student_coauthoring.md)
- 인증·참여자 계약: [인증과 학교 구성원 관리](07_identity_school_management.md). 학생별 교사 관리 참여를 지원하며 공유 계정을 사용하지 않는다.

## 1. 해결할 문제와 제품 목표

온책읽기를 준비하는 교사는 책의 적합성, 읽기 시간, 학생 간 속도 차이, 질문과 토론, 평가를 함께 결정해야 한다. 도서 목록과 활동지를 많이 제공하는 것만으로 이 판단 부담이 사라지지 않는다. 학생에게도 매번 독후감을 쓰고 교사 질문의 정답을 맞히는 경험만 남을 수 있다.

이 모듈은 학생이 온전한 작품을 읽거나 들으면서 자기 궁금함을 발견하고, 질문을 표현·선택·탐색·수정하도록 돕는다. 교사에게는 사용할 수업 흐름과 필요한 지원을 제공하고, 실제 읽기·대화 시간을 확보한다. AI가 좋은 질문을 먼저 만들어 주는 일은 보조 기능이다. 핵심 성과는 학생이 새로운 글에서 도움 없이도 자신의 질문을 만들고 탐색하는 능력이다.

`질문·탐구` 메뉴에서 단독으로 시작하거나 리더·이야기 여정에서 들어와 같은 질문 작업 공간을 사용한다. 단독 시작은 유효한 학급 참여 범위 안에서 개인 질문 세션을 만들며, 전체 단원·숙제·온라인 책 본문을 먼저 만들 필요가 없다. 교사 읽어주기·종이책·수업 주제도 출발점이다. 내 질문 작성 뒤 공유·근거 탐색·대화 보기로 전환하고, 필요한 본문 재독은 몰입형 리더에서 연다. [메뉴·독립/연계 실행 계약](08_platform_architecture.md)의 3장·4.5장을 따른다.

### 목표

1. 종이책·인쇄물·웹·듣기로 같은 작품과 장면에 접근한다.
2. 학생이 질문을 만들고 실제 수업에 사용한다.
3. 학년군과 읽기 지원 필요에 따라 표현 방식과 도움의 양을 조절한다.
4. 교사가 질문 전체를 전사·분류·답변·채점하지 않아도 수업이 진행된다.
5. AI가 없어도 모든 필수 수업 흐름이 작동한다.

### 비목표

- 문항 수·정답률·독서 속도로 학생을 공개 서열화하는 기능
- AI가 학생의 질문·감상·교사 평가를 최종 판정하는 기능
- 온전한 작품을 줄거리와 퀴즈만으로 대체하는 기능
- 학생 전원이 매 차시 온라인 질문과 답변을 제출해야 하는 운영
- 특정 질문 교수법의 자료·상표·워크시트를 허락 없이 상용 제품에 내장하는 일

## 2. 범위와 교육 원칙

초등 전 학년을 지원하되 1~2학년은 읽어주기·듣기·그림·말·함께 읽기를 중심으로 별도 설계한다. 학년은 추천의 출발점이며 읽기 능력이나 사고 능력의 고정 등급이 아니다. 저학년도 인물의 마음과 이유를 추론할 수 있고, 고학년도 어휘·사실 확인과 구술 지원이 필요하다.

| 학년군 | 기본 수업 경험 | 질문 표현·탐색 지원 | 피할 기본값 |
|---|---|---|---|
| 1~2 | 짧은 완결 이야기, 교사 읽어주기, 함께 소리 내기 | 장면 가리키기, 그림, 말, 교사 받아 적기, 짝 대화 | 타자·장문 쓰기·개별 기기 사용을 참여 조건으로 삼기 |
| 3~4 | 스스로 읽는 분량 확대, 장면과 사건 연결 | 모호한 질문 구체화, 관련 장면 찾기, 짝과 이유 비교 | 빠른 학생에게 문제만 추가하고 느린 학생은 가정 과제로 넘기기 |
| 5~6 | 긴 호흡 읽기, 관점·근거·함축 비교 | 여러 장면 연결, 질문의 전제 점검, 다른 해석 토론 | 추론·감상에 단일 모범답안을 강제하기 |

교육과정 연결은 `curriculum_version`, `grade_band`, `standard_code`, `mapping_rationale`, `reviewer_id`, `reviewed_at`으로 관리한다. 2022 개정 교육과정의 초등 전 학년 적용을 기준으로 하되, 과거 자료의 성취기준 코드를 자동 재사용하지 않는다. 연결이 검토되지 않은 자료는 ‘연계 검토 중’으로 표시한다. 온책읽기·온작품읽기·한 학기 한 권 읽기를 완전히 같은 개념이라고 설명하지 않는다.

## 3. 질문 분류 모델

PIRLS의 네 가지 읽기 이해 과정을 참고하되, 이 분류를 학생 질문의 등수나 점수로 바꾸지 않는다. 문학 읽기와 정보 읽기를 모두 지원한다. 분류는 수업을 고르게 설계하는 교사용 도구이며 학생에게 모든 용어를 외우게 하지 않는다.

| 코드 | 참고하는 이해 과정 | 학생 질문 예시 | 지도 목적 |
|---|---|---|---|
| QP1 | 명시적으로 제시된 정보 찾기 | ‘누가 이 말을 했지?’ | 필요한 사실·장면·어휘 확인 |
| QP2 | 직접적인 추론하기 | ‘왜 이때 도움을 거절했을까?’ | 가까운 단서에서 이유·관계 추론 |
| QP3 | 생각과 정보 해석·통합하기 | ‘처음과 마지막에 마음이 어떻게 달라졌을까?’ | 여러 장면과 관점을 연결 |
| QP4 | 내용과 텍스트 요소 평가·비판하기 | ‘이 설명만으로 이 인물을 나쁘다고 판단해도 될까?’ | 표현·근거·관점·판단 검토 |
| EXT | 창의·전이: 제품의 별도 교육 확장 | ‘다른 선택을 했다면 다음 사건은 어떻게 달라질까?’ | 대안 상상, 삶과 연결, 재창작 |

`EXT`는 PIRLS의 다섯 번째 공식 과정이 아니다. 창의적 질문이라고 항상 더 높은 수준인 것도 아니다. 한 질문에는 복수 과정이 필요할 수 있으며 분류하지 않은 상태도 허용한다.

다음 축은 이해 과정과 독립적으로 관리한다.

- 답의 형식: 열린 질문 / 닫힌 질문 / 미분류
- 질문의 출처: 학생 / 교사 / 검수된 콘텐츠 / AI 제안
- 학생이 받은 도움: 독립 / 문장 시작 틀 / 대화 도움 / 예시 참고
- 탐색 경로: 본문 다시 읽기 / 장면 비교 / 친구와 대화 / 추가 자료 / 아직 미정
- 현재 상태: 새 질문 / 선택됨 / 탐색 중 / 잠정 답 / 남은 질문 / 돌아봄

닫힌 질문도 사실 확인과 생각 점검에 유용하다. ‘왜’로 시작한다고 반드시 추론 질문인 것은 아니며 본문에 답이 직접 제시되어 있을 수도 있다. AI 분류 결과는 제안으로만 저장하며 교사·학생의 원래 표현을 덮어쓰지 않는다.

## 4. 핵심 사용자 흐름

### 4.1 교사의 수업 준비

1. 학급, 학년군, 작품·판본, 확보한 차시, 기기 사용 여부를 고른다.
2. 추천안에서 본문 분량·수업목표·질문 루틴·선택 활동을 함께 미리 본다.
3. 읽기 지원을 선택한다. 예: 교사 읽어주기, 어휘 카드, 큰 글자, 짝 읽기.
4. 인쇄 또는 웹으로 수업 자료를 배부한다. 학생 로그인 없이 교사 화면과 종이만으로도 실행 가능하다.
5. 관찰할 항목을 1~2개 선택하고 수업을 시작한다. 전원 평가가 필요하지 않다.

### 4.2 학생의 읽기와 질문

1. 작품을 읽거나 듣고 궁금한 곳·이상한 곳·이해되지 않는 곳을 표시한다.
2. 먼저 자기 말·그림으로 질문을 표현한다. ‘여기가 이상해요’처럼 미완성 표현도 허용한다.
3. 짝·모둠과 질문을 나누고 지금 알아볼 질문을 선택한다.
4. 탐색 방법을 골라 답을 시도한다. 책으로 돌아가거나 다른 해석을 듣는다.
5. 알게 된 것과 아직 남은 것을 구별한다. 필요하면 질문을 고치거나, 유지한 이유를 말한다.
6. 질문을 다음 읽기, 토론, [낭독극의 인물 해석](04_readers_theater.md), [공동책의 사건 선택](06_student_coauthoring.md)에 연결한다.

### 4.3 시간 구성 예시

40분 수업의 한 예시는 읽기 20분, 학생 질문 5분, 대화·탐색 10분, 마무리 5분이다. 이는 검증된 최적 비율이 아니라 수업안의 예시다. 작품 분량과 학생 필요에 따라 조정하며 실제 읽기 시간을 먼저 확보한다.

질문 만드는 방법을 처음 가르치는 차시는 별도로 확보한다. 처음부터 짧은 루틴만 제시하고 학생이 질문 방법을 알고 있다고 가정하지 않는다. 일상 루틴은 ‘표시 → 내 말로 질문 → 선택 → 탐색 → 돌아보기’이며, 정식 QFT를 몇 분으로 축약해 그대로 수행했다고 표시하지 않는다. QFT 공식 자료는 첫 전 과정에 최소 40~45분, 익숙해진 뒤 20~30분을 안내한다.

## 5. 기능 요구사항

‘필수/확장’은 이 모듈 안의 구분이며, 제품 전체의 P0/P1/P2 출시 순서는 [통합 계획](../main.md)을 따른다.

| ID | 모듈 내 구분 | 요구사항 |
|---|---|---|
| INQ-001 | 필수 | 학급·학년군·작품 판본·차시·기기 조건을 기준으로 수업 계획을 저장한다. 학교·학급이 없는 학생 활동은 생성하지 않는다. |
| INQ-002 | 필수 | 읽기 구간은 페이지뿐 아니라 장면·문단 식별자로 지정한다. 웹·인쇄·음성에서 같은 구간을 찾을 수 있어야 한다. |
| INQ-003 | 필수 | 학생 질문 입력 전에 AI 질문 목록을 기본 표시하지 않는다. 본문 표시·구술·그림·종이 기록을 먼저 선택할 수 있다. |
| INQ-004 | 필수 | 질문 원문, 표현 방식, 작성자, 판본, 선택한 근거 위치를 보존한다. 맞춤법·문장 완성도가 낮아도 저장·참여할 수 있다. |
| INQ-005 | 필수 | 질문을 전원 온라인 등록하지 않아도 된다. 교사는 모둠 선택 질문 또는 구술 질문만 대리 기록할 수 있으며 대리 기록임을 표시한다. |
| INQ-006 | 필수 | 학생 또는 모둠은 알아볼 질문과 선택 이유를 정한다. 교사는 수업목표·시간에 맞춰 채택 여부를 조정할 수 있다. 선택되지 않은 질문을 틀린 질문으로 표시하지 않는다. |
| INQ-007 | 필수 | 질문별 탐색 방법, 근거 위치, 잠정 답, 남은 궁금함을 연결한다. 답 미발견·탐색 보류를 정상 상태로 지원한다. |
| INQ-008 | 필수 | 질문 수정 시 이전 표현과 새 표현, 작성 주체를 보존한다. 유지했을 때도 그 이유를 남길 수 있다. |
| INQ-009 | 필수 | 사실 확인·추론·통합·평가·창의 확장을 분류하되 자동 점수·우열·질문 수 순위를 만들지 않는다. |
| INQ-010 | 필수 | 문장 시작 틀, 교사 시범, 짝 대화를 정적 지원으로 제공한다. 학생이 도움을 요청할 수 있고 교사는 도움의 양을 조정한다. |
| INQ-011 | 필수 | 도움을 점진적으로 줄이는 수업안을 제공하되, 학생의 접근성 지원을 자동 제거하지 않는다. 독립 시도와 도움받은 시도를 구분한다. |
| INQ-012 | 필수 | 교사 화면은 모둠 선택 질문과 관찰 대상만 우선 보여준다. 모든 질문에 피드백해야 완료되는 조건을 만들지 않는다. |
| INQ-013 | 필수 | 교사 평가는 수동 작성·수동 확정한다. AI 제안이 있더라도 승인 전 평가·생활기록 관련 최종 값으로 쓰지 않는다. |
| INQ-014 | 필수 | 학생 Google 계정을 기본 전제로 삼지 않는다. 교사 관리 참여자·제한된 학급 참여 세션 또는 기기 없는 수업으로 진행할 수 있다. |
| INQ-015 | 필수 | 질문·응답의 기본 범위는 작성자·교사다. 모둠 또는 학급 공유는 수업 목적에 따라 명시적으로 선택하며 외부 공개 버튼은 제공하지 않는다. |
| INQ-016 | 필수 | 단원/여정·`assignment_id` 연결은 선택이다. 질문 세션만으로 시작하고 기존 질문 활동을 나중에 여정에 연결할 수 있다. 연결해도 매 질문·매 읽기 구간의 제출이나 학급 공개를 강제하지 않는다. |
| INQ-017 | 확장 | 교사 화면에서 유사 질문 묶기와 관련 근거 위치를 AI가 제안할 수 있다. 원문·작성자·개별 질문 관계는 보존하고 자동 병합·삭제하지 않는다. |
| INQ-018 | 확장 | 학생이 요청한 AI 도움은 짧은 되묻기·탐색 방향으로 제한할 수 있다. 답을 즉시 보여주거나 질문을 대신 완성하는 것을 기본값으로 두지 않는다. |
| INQ-019 | 필수 | AI 미설정·사용 중지·한도 초과·서비스 오류 시 정적 지원과 교사 수업으로 계속 진행한다. 유료 서비스로 자동 대체하지 않는다. |
| INQ-020 | 필수 | 단원 종료 후 새 글에 대한 독립 질문 시도를 선택할 수 있다. 이전 AI 대화 수나 질문 개수를 질문 역량 점수로 전환하지 않는다. |

## 6. 교사 관찰과 학생 성찰

아래는 제품 파일럿용 관찰 틀이며 표준화된 검사도구가 아니다. 교사는 학급 상황에 맞게 항목을 고르고 일부 학생을 순환 관찰한다. 학생 간 공개 비교·자동 총점·등급 낙인을 만들지 않는다.

| 관찰 축 | 도움을 받아 시작 | 일부 스스로 수행 | 스스로 수행하고 설명 |
|---|---|---|---|
| 자립성 | 시범·단서로 궁금함을 표현 | 일부 도움 뒤 질문을 표현·선택 | 질문과 알아볼 이유를 스스로 말함 |
| 연결·근거 | 관련 장면을 함께 찾음 | 장면·경험·단서를 질문에 연결 | 적절한 단서와 탐색 방법을 선택하고 설명 |
| 수정·성찰 | 재독·대화를 안내받음 | 도움을 받아 질문·생각을 점검 | 질문·생각을 고치거나 유지한 이유를 설명 |

텍스트 밖 질문도 허용한다. 이때는 이미 정답 근거를 갖고 있는지보다 무엇에서 궁금함이 생겼고 어떻게 알아볼지 관찰한다. ‘수정’은 매번 문장을 바꾸는 의무가 아니다. 저학년은 구술·그림, 쓰기 지원이 필요한 고학년도 구술로 같은 능력을 드러낼 수 있다.

단원 종료 기록은 대표 질문과 이후 변화 한 쌍 정도로 충분한 운영을 기본으로 한다. 교사가 모든 활동을 다시 입력하지 않도록 질문 선택·근거 표시·성찰에서 이미 만들어진 자료를 참조한다. 기록 생성은 교사 확정 전 초안으로 유지한다.

## 7. 데이터와 권한 계약

독립 `reading` 서비스의 애플리케이션과 Firebase Auth·Firestore·Cloud Storage를 목표 구조로 한다. 현재 로컬 프로토타입은 데이터 어댑터와 합성 참여자만 사용하며 실제 Firebase에는 연결하지 않는다. 이 문서는 프로젝트 생성·클라우드 변경·배포를 수행하지 않는다. 실제 서버·문서·파일 권한 명세는 [PRD 08](08_platform_architecture.md)을 따른다. 아래 엔터티 이름은 논리적 데이터 계약이며 물리적 컬렉션·경로 구성은 PRD 08에서 정한다.

학생 질문·탐구 운영 문서에는 `school_id`, `class_id`가 있다. Firebase Auth는 신원을 확인하며, 서버는 요청마다 최신 membership의 실제 학교·학급 소속·역할·활성 참여 상태를 확인한다. Firestore·Storage Security Rules도 허용된 접근 경로와 범위를 검증한다. 서버 경로는 Rules를 이유로 자체 권한 검증을 생략하지 않으며, 오래된 토큰 클레임·클라이언트의 학급 ID·이름 선택만으로 접근을 허용하지 않는다. 단원/여정은 선택이며 학교·학급 권한은 단독 사용에서도 유지한다. 디지털 책을 연결한 활동은 승인된 `edition_id`·`edition_revision_id`를 참조한다. 종이책·구술·주제 활동은 서지/쪽수/장면/주제 참조를 사용하고, 없는 디지털 판본을 필수 값으로 요구하지 않는다.

로컬의 역할 전환·접근 거절 화면은 UX 모의 상태다. 실제 Firebase 인증, membership 변경 후 접근 철회, Security Rules 차단은 연동 후 별도로 검증하며 로컬 시연으로 통과 처리하지 않는다.

| 논리 엔터티 | 주요 필드 | 읽기·쓰기 범위 |
|---|---|---|
| inquiry_units | id, school_id, class_id, edition_id?, grade_band, curriculum_version, lesson_plan_revision, status | 선택적으로 구성하는 수업/여정. 담당·협력 교사와 배정 참여자 |
| inquiry_sessions | id, unit_id?, school_id, class_id, activity_id, source_refs, segment_ids?, planned_minutes?, assignment_id?, status | 단독 개인/허용 모둠 세션도 가능. 작성자와 담당 교사, 명시적으로 공유한 참여자 |
| student_questions | id, session_id, school_id, class_id, author_profile_id, author_group_id?, source, expression_mode, original_text?, artifact_id?, anchor_ids, visibility, revision | 원칙적으로 작성자·교사. 선택한 모둠·학급 공유만 확대 |
| question_revisions | question_id, school_id, class_id, revision, prior_revision, editor_profile_id, origin, text_or_artifact_ref, reason? | 해당 질문 접근 범위. 타인 기여를 무단 소유권 변경 불가 |
| inquiry_attempts | question_id, school_id, class_id, exploration_method, evidence_anchor_ids, tentative_response?, unresolved_note?, assistance_level | 학생·모둠·교사 중 설정된 범위 |
| question_selections | session_id, question_id, school_id, class_id, selected_by, reason?, scope | 해당 수업 범위 |
| inquiry_observations | id, school_id, class_id, learner_profile_id, criterion, observation, evidence_ref, status, confirmed_by?, confirmed_at? | 교사. 학생에게 공개한 피드백만 별도로 제공 |

학생 글·음성·그림·질문 원문은 보호된 업무 데이터로 취급한다. 영구 음성 저장은 기본 기능으로 가정하지 않으며 원문 보존이 필요할 때도 목적·보관·삭제 정책을 적용한다. 실명·질문 원문·답변 원문·프롬프트·음성 전사를 분석 로그에 복제하지 않는다. 공용 기기의 임시 입력은 세션 종료 시 지우고, 로컬 영구 보관은 기본으로 켜지 않는다.

### 이벤트

공통 이벤트 필드: `event_id`, `schema_version`, `event_type`, `occurred_at`, `received_at`, `school_id`, `class_id`, `actor_profile_id`, `resource_type`, `resource_id`, `revision_id`, `request_id`, `trace_id`, `outcome`, `source`, `metadata_allowlist`.

`source`는 `web`, `paper`, `teacher_import` 중 하나다. 분석용 actor는 내부 식별자이며 필요 이상으로 연결하거나 외부 분석 서비스에 전달하지 않는다. 이벤트 이름과 허용 메타데이터는 다음으로 제한한다.

| 이벤트 | 허용 메타데이터 예 | 금지 |
|---|---|---|
| inquiry.session_started | grade_band, mode, planned_minutes | 학생 명단·실명 |
| inquiry.question_created | expression_mode, origin, assistance_level | 질문 원문·그림·음성·본문 인용 |
| inquiry.question_selected | selection_scope, selector_role | 선택 이유의 자유 텍스트 |
| inquiry.exploration_recorded | method_code, evidence_count, unresolved_flag | 답변 원문·검색어·외부 링크의 민감 쿼리 |
| inquiry.question_revised | origin, revision_number, changed_flag | 수정 전후 원문 |
| inquiry.observation_confirmed | criterion_codes, confirmation_role | 평가 서술·학생별 점수 원문 |
| inquiry.assistance_used | assistance_type, provider_enabled_flag, outcome_code | 프롬프트·모델 응답·비밀키 |

## 8. 화면과 상태

| 화면 | 상태 | 반드시 보여줄 내용·동작 |
|---|---|---|
| 교사 수업 준비 | 초안 / 검토 중 / 준비 완료 / 보관 | 작품·판본, 실제 읽기 분량, 차시와 선택 활동, 준비물 |
| 학생 읽기 | 배정 전 / 읽기 가능 / 연결 끊김 / 종료 | 허용 구간과 접근 가능한 대체 방식. 연결 끊김에도 종이·교사 화면으로 안내 |
| 내 질문 | 비어 있음 / 임시 / 저장됨 / 수정됨 / 공유 대기 | 자유로운 표현 시작, 도움 요청, 저장 여부. 질문이 없다고 실패 표시하지 않음 |
| 모둠 질문 선택 | 후보 있음 / 선택됨 / 보류 | 원래 질문과 선택 이유. 교사가 대신 쓴 문장과 구별 |
| 탐색 | 진행 중 / 잠정 답 / 미해결 / 돌아봄 | 본문 돌아가기, 근거, 남은 질문, 다음 탐색 |
| 교사 관찰 | 관찰 없음 / 초안 / 수동 확정 | 근거 자료, 도움 수준, 교사 편집·확정. 자동 확정 없음 |
| AI 지원 | 꺼짐 / 사용 가능 / 요청 중 / 제한 / 오류 | 계속 사용할 정적 도움. 비용·권한 미확인 시 호출 없이 중단 |

저장 충돌은 마지막 저장으로 조용히 덮어쓰지 않고 최신 판본과 내 임시 입력을 비교하게 한다. 권한 철회·학급 종료는 접근 불가로 전환하되 원문이 오류 로그에 노출되지 않는다.

| INQ-AC-02 | 002 | 인쇄본의 장면 식별자와 웹·음성 위치가 같은 승인 판본으로 연결된다. 다른 판본이면 명시적으로 경고하고 자동 치환하지 않는다. |
| INQ-AC-03 | 003,010~011 | 첫 질문 입력 전 AI 예시가 강제로 보이지 않는다. 도움 사용 후에도 원 질문·도움 수준이 보존되고 지원을 다시 요청할 수 있다. |

| INQ-AC-05 | 012~013 | 교사가 전원 질문에 답하지 않아도 수업을 종료한다. 평가 초안은 교사 확정 없이 최종 기록으로 나가지 않는다. |
| INQ-AC-06 | 014~015 | 다른 학교·다른 학급·권한 철회 사용자가 ID·URL을 바꿔 질문·그림·평가를 읽거나 수정할 수 없다. 비공개 파일 링크에도 같은 검증을 적용한다. |
| INQ-AC-07 | 016 | 과제 없는 수업과 과제 연결 수업이 모두 작동한다. 종이 참여를 자동 미제출·미참여로 처리하지 않는다. |

업무 절감은 기존 수업 대비 선정·준비·인쇄·수업 중 문제 대응·평가·정리의 총시간으로 확인한다. 첫 사용과 두 번째 사용을 구분하고 개발자·연구자가 대신 처리한 시간도 포함한다. 교육 효과는 AI 없이 새 글에 질문하는 시도, 근거 연결, 수정 이유 설명을 별도로 관찰한다. 소규모 파일럿으로 장기 독해력 향상을 인과적으로 단정하지 않는다.
