## 책 공방과 실제 WebP 삽화

공방의 현재 단계는 `씨앗 고르기 → 이야기 그리기 → 한 장씩 쓰기 → 그림 입히기 → 다시 읽기 → 책으로 만나기`이다. 단계는 자유롭게 오가며 직접 집필할 수 있다.

1. 4장 직접 쓰기 → 검토 3항목 확인 → 고정 판본을 서재에 놓기 → A5 전권 PDF 다운로드를 통과했다. 결과는 표지와 본문 4장, 합계 5쪽이다.
2. 실제 WebP 파일을 고르고 직접 넣은 삽화 표시를 확인했다. 그림 출처를 기록한 뒤 v17 전권 A5 PDF를 내려받았다.
3. 결과 파일 `검증용 창작책 · 함께 부른 구름-v17-A5.pdf`는 579,705 bytes, 표지 포함 5쪽의 A5 문서이다. SHA-256과 도구 명령은 [별도 PDF 검증](pdf-final-check.md)에 보관했다.
4. **물리적 2쪽, 첫 장면**을 독립 렌더하여 업로드된 그림·한글 본문·그림 출처·`2 / 5` 쪽번호가 정상 표시되고 서로 겹치거나 잘리지 않는 것을 확인했다. 나머지 4쪽의 시각 검수나 실제 종이 출력까지 확인했다는 뜻은 아니다.
5. 전체 백업 복원 후 공방 v17의 4장·업로드 삽화·그림 출처가 유지된 것을 다시 확인했다.

한 기기의 학생 팀 모드는 차례별 작성자·기여·피드백을 기록하는 방식이다. 여러 기기 동시 편집이나 인증된 학생별 저작 기여를 검증한 기능이 아니다. 고정 판본 저장은 이 브라우저 서재에 사본을 남기는 동작이며 외부 출판·공개가 아니다.

## 전체 백업·복원

현재 저장은 같은 브라우저의 IndexedDB를 사용한다. 실제 검증은 다음 순서로 진행했다.

1. `/guide`에서 전체 작업 JSON을 다운로드했다. 읽기·질문·서재 상태, 책 공방, 학습 기록지의 **3개 저장소**를 포함했다.
2. 전체 백업 파일을 선택해 지원 구조와 3개 저장소 검증 결과를 확인했다.
3. 화면 안의 `현재 자료를 먼저 내려받고, 백업에 있는 작업 저장소로 교체하는 것을 확인했어요.`에 체크했다. 체크 전에는 복원 버튼을 사용할 수 없다.
4. 복원 버튼으로 현재 자료의 `onbook-before-restore.json` 다운로드를 확인하고, 저장소 교체·새로고침까지 완료했다.
5. 복원된 내용을 다시 열어 FORM-09 실제 답변, 본문 2장면·책갈피 1개·글만 읽기 선택, 자기 질문과 답변, 공방 v17의 4장·업로드 삽화·출처를 각각 대조했다.

전체 복원은 백업에 있는 해당 저장소를 교체하며 병합하지 않는다. 아직 새 화면에서 열지 않은 이전 localStorage 공방·기록장도 검증해 백업에 포함하는 경로, 손상 파일 거절, IndexedDB 우선 적용은 자동 검사로 확인했다. 이 결과는 계정 기반 동기화, 모든 기기 간 이전, 브라우저 데이터 삭제 후 자동 복구를 보장하지 않는다.

## 디자인·글꼴·반응형 확인

- 사용자가 승인한 밝은 색연필 방향을 정적 자산으로 적용했다. 기능 아이콘 **16종**은 승인 범위의 구독 내장 이미지 생성으로 제작했으며 원본 PNG와 웹용 WebP를 보관한다. 이번 최종 검증에서 새 이미지를 생성하지 않았다.
- 화면 글꼴용 고운돋움·고운바탕의 로컬 WOFF2, PDF용 로컬 나눔고딕을 사용한다. 정적 자산을 표시할 때 별도의 AI 생성 요청을 실행하지 않는다.
- 데스크톱의 밝은·어두운 테마와 한국어·영어 화면을 확인했다. 흰 종이 기반의 색연필 삽화를 다크 모드에서 반전하거나 어둡게 변형하지 않는다.
- 모바일 물리적 화면 폭 390 환경에서 CSS 레이아웃 폭 344로 확인했으며, 문서의 `scrollWidth`와 `clientWidth`가 같아 가로 넘침이 없었다. 물리적 화면 폭과 CSS 뷰포트 폭은 다른 값이다.
- 이 확인은 해당 브라우저·화면 크기의 실기이다. 모든 기기, 스크린리더, 저속 네트워크, 학교 프린터를 포괄하는 접근성·성능 인증은 아니다.
